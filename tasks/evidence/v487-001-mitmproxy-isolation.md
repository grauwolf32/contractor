# Общий mitmproxy и изоляция сессий

Эксперимент выполнен 2026-11-25 на Python 3.13.16, macOS arm64,
mitmproxy 12.3.1. Точные версии и результаты находятся в
[v487-001-mitmproxy-isolation.json](v487-001-mitmproxy-isolation.json).

Из корня Runtime checkout воспроизводится следующая команда.

```sh
cd runtime
uv run python ../scripts/experiments/mitmproxy_shared_sessions.py \
  --output ../tasks/evidence/v487-001-mitmproxy-isolation.json
```

В каждом сценарии счётчик вызовов конструктора подтверждает один Master.
Общий engine запускается с процессными defaults, приватные CA находятся в
сессиях. HTTPTransport
и scanner ingress используют действующие production методы через session facade.
У каждой сессии отдельные pools, flows, identity state и authority callback.
Фикстуры поднимают настоящие локальные TCP/TLS endpoints на RFC1918-интерфейсе.
Внешние targets, Gateway и конфигурация из `configs/` не используются.

| Сценарий | Наблюдаемый результат |
| --- | --- |
| HTTP/1.1, четыре владельца | Один origin и одинаковые identity/credential names получают четыре разных auth/cookie пары. Target принимает четыре отдельных соединения. |
| HTTP/2, четыре владельца | Та же проверка на нативных HTTP/2 layers. Отдельные соединения ограничивают failure domain каждой аллокации. |
| Негативный контроль маршрутизации | Преднамеренный вызов соседнего owner обнаруживается сравнением заголовков, фактически полученных target. |
| Scanner CONNECT + HTTP/2 | Два входа направляют запросы в соответствующий HTTPTransport. Каждый клиент проверяет сертификат своей proxy CA. Чужой токен на другом listener и токен закрытого входа не доходят до target. Закрытие входа joins активный запрос. |
| Отмена TLS callback в потоке | Первая операция ждёт управляемый барьер, соседняя завершается. Отмена первой joins поток, поздний application send отсутствует. |
| Разные CA с глобальными options | Обнаружен провал. CA первого engine разрешает запрос сессии с другим trust bundle, а сертификат её собственного CA отклоняется. |
| Разные CA с контекстными options | Свой CA разрешён, чужой отклонён. Три проверки выполняются конкурентно через реальные TLS-соединения. |
| Redirect и pre-send retry | Cookies и Authorization сохраняют владельца. Два искусственных отказа TCP до отправки учитываются отдельно и успешно повторяются в действующих рамках retry. |
| Отмена DNS и HTTP/2 queue | DNS joins работу до возврата отмены. Закрытие сессии отменяет активный и queued запрос, соседний owner продолжает работу. |
| Восемь циклов по четыре сессии | 32 сессии освобождают weak references, private directories и target sockets. Native TLS caches после cleanup пусты. |

В кейсах cleanup планировщику передаётся один шаг для исполнения callbacks
уже joined задач перед проверкой weak references. Проверка не ожидает произвольный
интервал по wall clock. Барьеры управляют DNS, TLS и held HTTP/2 stream.

Вывод — общий Master применим при отдельном TLS/connection state сессий.
Общие глобальные TLS options дают наблюдаемое нарушение изоляции.

Прототип устанавливает один стабильный объект `ctx.options`. Доступ к его
полям разрешается через ContextVar конкретной сессии. Request и ingress
устанавливают контекст на входе и восстанавливают при выходе. `asyncio.to_thread`
переносит этот контекст в native TLS callback. Вне выданной сессии TLS options
недоступны. Глобальные options не переключаются вокруг await.

Для production требуется перенести текущие exchange/ingress методы в session
owner и создавать общий Master при Runtime composition. Один процессный
инициализатор заменяет allocation-specific capture/restore. Session cleanup
сохраняет существующие joins и очищает native TLS caches перед удалением
приватных файлов, не закрывая соседние сессии.

Цена адаптации — стабильный options proxy, установка/сброс ContextVar на двух
границах и выделение session lifetime из текущего engine. Сам proxy занимает
менее десяти строк. Основной объём работы — перемещение существующего кода
и регрессии, точный production diff проверяется во второй группе. Копировать
реализацию TLS из библиотеки или менять её файлы не требуется.

Привязка к private API закреплённой версии остаётся принятой ценой интеграции.
V487-002 владеет startup guard и переносом этих проверок на обычный production
путь. При обновлении mitmproxy заново проверяются globals, ContextVar propagation
и cache ownership. Реальные runtime-wide lease/Podman/process-loss сценарии
относятся к последующим задачам и этим экспериментом не подтверждены.

Проверки завершены. Исполняемый эксперимент прошёл девять сценариев.
`make lint` прошёл. `make test-runtime` завершился с 6690 passed и 134
объявленными skips, оба report validators прошли, включая 587 compaction cases.
Платформенные и опциональные интеграционные skips перечислены в
verification задачи и не считаются пройденными сценариями. Heavy-I/O флаг
оставался выключенным. Для этой задачи тестовая база не создавалась.

В первых запусках окружение не находило Go и использовало Homebrew ffuf
2.1.0-dev, который штатно отвергается controlled HTTP. После исправления
PATH с Go 1.26.10, Node 24.20.0 и ffuf 2.3.0 все 18 ffuf-тестов и итоговый
полный Runtime gate прошли. Репозиторный код для исправления окружения
не менялся.

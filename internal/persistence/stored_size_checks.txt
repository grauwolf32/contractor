# Stored-size CHECK registry: PER-R44 in docs/spec/platform/persistence.md.
#
# TestPostgresStoredSizeChecksHaveADisposition
# (internal/persistence/postgres/stored_size_checks_postgres_test.go) reads
# every CHECK constraint of a migrated schema whose definition calls
# octet_length. It fails on a constraint without a line here, on a line for a
# constraint the schema lacks, on a cited entry that limits.md does not
# register, and when the Enforced by cell of a limits.md row and this file
# disagree about which constraints enforce that row.
#
# One line per constraint: the constraint name, then its disposition.
#
#   LIM-<area>-<n>        the constraint enforces this registered bound on the
#                         stored value, and the row names the constraint in
#                         its Enforced by cell;
#   above:LIM-<area>-<n>  the constraint is a storage backstop that admits
#                         more than this registered bound, which the Server
#                         checks before it writes the value;
#   invariant: <reason>   a fixed width or a consistency rule between columns,
#                         which bounds nothing a caller or a domain rule sizes.
#
# A line may combine several LIM and above: tokens when the constraint bounds
# more than one quantity. For jsonb columns the constraint measures the stored
# text, octet_length(column::text), which jsonb re-serialisation can make
# longer than the JSON the Server submitted (LIM-API-25).

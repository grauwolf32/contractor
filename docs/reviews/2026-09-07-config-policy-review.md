# Проверка и исправление конфигурации

Дата: 2026-09-07. Отчёт обновлён после согласованных правок.

## Итоговая конфигурация

- Основные политики: `planner@2` и `worker@2`. Обе используют окно контекста
  118 000 токенов, до 16 384 выходных токенов, 200 вызовов модели,
  2 500 000 суммарных токенов и температуру 0.1. Planner допускает
  200 вызовов Worker; Worker — 200 вызовов инструментов.
- [`summarizer@1`](../../configs/model-policies/summarizer.yaml) — отдельная
  служебная политика на тот же `worker-model`: окно 118 000, один вызов,
  до 8192 выходных токенов, без инструментов и Worker calls.
- В LiteLLM остаются два алиаса: `planner-model` и `worker-model`, оба
  выбирают `openai/qwen/qwen3.8-27b`. Таймауты обеих моделей и общий
  `request_timeout` установлены в 240 секунд. Worker client timeout —
  300 секунд; `plannerTimeout` — 30 минут.
- Параллельно добавленный пример Audit completion сохраняет свою политику
  `audit_completion_worker@1`; она не относится к упрощению общих planner/worker
  политик и в этой правке не менялась.

## Устранённые замечания

В `openapi-from-analysis@2`, `openapi-from-workspace@5` и
`openapi-from-workspace-streamline@1`, а также их вариантах с Memory,
валидация OpenAPI при ошибке использует
обычный `retry` с `maxAttempts: 2`. Рабочий `strong-oas-review` удалён;
тестовые профили эскалации сохранены в testdata. Повтор сохраняет эффективную
политику Run. Он выполняется только для retryable-ошибок; остальные ошибки
завершают Stage сразу, согласно существующей реализации scheduler.

Для 30 обычных Worker templates (включая варианты с Memory) включён терминальный summarizer с
`contextWindowRatio: 0.8`, то есть порогом 94 400 токенов входного контекста
по данным провайдера. Порог ниже 101 616 токенов, остающихся при резерве
16 384 токенов под обычный ответ. Отдельный `cumulativeBudget` не добавлен.

Одиннадцать Audit Worker templates (включая варианты с Memory и completion) оставлены без summarizer: они обязаны отправить
канонический результат через `audit-results`. Резюме без инструментов не может
заменить недостающую отправку результата; контракт `audit-check-results@1`
прямо запрещает такой summarizer.

Инструкции summarizer подключены через `summarizer.instructions.ref` к общему
[`terminal-summarizer.md`](../../configs/instructions/terminal-summarizer.md).
Текст фиксируется вместе с digest и проверяется на максимум 8000 Unicode-символов.
Оценка 2000 токенов приблизительная. V47-003 отменён: локальной оценки
«байт = токен» и обрезки истории по ней больше нет. Прежнее ограничение
документа в 512 КиБ сохраняется; отдельная стратегия compactification не добавлена.

## Сохраняющиеся особенности

- Summarizer завершает исполнение Worker и не возобновляет цикл на сжатой
  истории. Он не создаёт отсутствующие обязательные артефакты. Некорректный
  или неполный результат завершится ошибкой.
- Порог использует usage из ответа модели и проверяется на безопасной границе
  цикла. Он не гарантирует предотвращение любого переполнения: первый запрос
  или большой скачок входного контекста всё ещё могут быть отклонены прокси.
- Метаданные окна Planner не включают для него summarizer.
- Новые совокупные токенные бюджеты Workflow/Run/Audit не добавлены. Лимиты
  модели, инструментов, повторов и времени исполнения сохраняют разные функции.
- Короткая проверка на LM Studio выполнена (ниже). Она не измеряет качество
  на длинной истории, насыщение очереди или предельное окно контекста.

## Реальная проверка LiteLLM / LM Studio

Проверка выполнена 2026-09-07 через временный LiteLLM с конфигом
`deploy/litellm/litellm_config.yaml`. Образ соответствует закреплённому в
`deploy/litellm/run.sh` digest `sha256:2e8517e2bed423c50ab7e40fb1ac0a9cbe62a764e9d65161d871fb6a9bf75a2d`.
Upstream: `http://192.168.1.217:1234/v1`, модель `qwen/qwen3.8-27b`.
`/v1/models` прокси вернул ровно два алиаса: `planner-model`, `worker-model`.

| Проверка | Результат | Время | Вход / выход / всего токенов |
| --- | --- | --- | --- |
| `planner-model` | `CONFIG_OK`, usage присутствует | 1,61 с | 61 / 36 / 97 |
| `worker-model` | `CONFIG_OK`, usage присутствует | 0,45 с | 61 / 36 / 97 |
| Summarizer с инструкциями из конфига | Валидный `WorkerModelResult`, точный subtask ID, один вызов | 3,47 с | 253 / 292 / 545 |

Для двух обычных запросов использовались значения из YAML: `maxOutputTokens: 16384`,
`temperature: 0.1`. Для summarizer — `8192`, `0.1` и метаданные окна `118000`.
Проверка использовала Runtime OpenAI-адаптер и настоящий одноразовый ADK summarizer,
без вызовов инструментов и без создания Run в постоянном хранилище.

Первый запуск временного контейнера в стандартной rootless-сети не смог соединиться
с upstream (LiteLLM вернул HTTP 500 с connection error). Хост обращался к LM Studio
успешно. Повторная проверка прошла с `--network host`, при этом прокси слушал только
`127.0.0.1` на временном порту. Настройки постоянного развёртывания не менялись;
доступность upstream из сети штатного deployment этой проверкой не подтверждена.
Временный контейнер и файл его одноразового ключа удалены.

Полный набор тестов репозитория и реальные workflow/e2e-запуски не выполнялись.

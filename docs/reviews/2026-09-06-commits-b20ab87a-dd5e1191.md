## P2 — Запоздавший GET перезаписывает результат сохранения Git SSH key

Коммит: `195db3b5` — `feat(ui): add personal Git keys and shared artifact import dialog`.

Место: [GitKeySettings.change](../../ui/src/routes/settings/git-key.tsx#L41),
особенно запись `cache.setQueryData(gitKeyQueryKey, state)` на строке 48.
Кнопка сохранения на строке 111 доступна во время первоначального GET, если
пользователь уже ввёл ключ.

Условие: ответ `GET /v1/settings/git-key`, начатого при открытии Settings,
приходит после успешного `PUT` и содержит более старое состояние.

Воспроизведение:

1. Открыть Settings; задержать первоначальный GET с `{configured: false}`.
2. Ввести ключ и сохранить. PUT успешно возвращает `{configured: true, ...}`.
3. UI показывает `Git SSH key saved.` и настроенный ключ.
4. Доставить старый ответ GET. Он заменяет данные того же query на
   `{configured: false}`.

После этого UI сообщает, что ключ не настроен, и отключает `Remove Git key`,
хотя Server уже сохранил ключ. Сообщение об успешном сохранении при этом остаётся.
У приложения отключён `refetchOnWindowFocus`, поэтому переключение вкладок само
по себе не исправляет состояние. Та же конкуренция чтения и записи возможна
при замене или удалении ключа во время повторного запроса metadata.

Причина: мутация пишет результат в cache, не отменив запрос, который затем
может записать устаревшее значение в тот же query.

Проверка: в отдельном снимке добавлен тест с управляемым Promise для GET.
На исходном коде он падает: ожидалось `{configured: true}`, получено
`{configured: false}`. После добавления
`await cache.cancelQueries({queryKey: gitKeyQueryKey})` перед мутацией в том же
снимке тест проходит. Это проверка причины и направления исправления;
продуктовый файл в основном workspace не изменялся.

Рекомендация: отменять активное чтение этого query перед мутацией и согласованно
обновлять/перепроверять metadata после её завершения. Добавить проверки как
сохранения, так и удаления с запоздавшим GET. Секрет по-прежнему должен оставаться
вне shared query/mutation cache.

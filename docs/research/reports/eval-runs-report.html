0 · Measurement methodology & load-bearing caveats

  • n=1 runs carry ±40% variance from run-length alone (CLI workflow) and single-pass recall swings 0.13↔0.73 across repeats. Only deterministic mechanics and large effects are measurable at n=1.
  • The detection eval UNDER-measures precision & recall (incomplete ground truth + strict one-to-one/line matching). Source-level FP audits showed ~half of "FPs" are real bugs the GT/matcher can't credit. Audit FP counts before believing a precision regression.
  • Recall is the priority metric (security scanner: a missed bug > an extra triaged finding). Prefer recall-preserving / cost levers; never generation-suppression.
  • Controlled comparison = pass@3, single-pass agent (equal work both arms), 3 projects, relative deltas only.

2.4 · Workshop convergence investigation → the `converge` prompt fix

Root cause of the workshop recall collapse: failing cases churn an annotate → restore → re-annotate loop — restores ran 2.4–5.8× the annotate count (110 total restores across 15 cases). Mechanism: annotate_trace refuses duplicates, so to revise an annotation the agent must restore the whole path and re-annotate; on uncertain cases it never commits. Not caused by the QW changes (default-off, verified).

The convergence fix wins decisively. `converge.md` = v7 + HARD RULE 9 (commit discipline: annotate once, cap restores, stop on no-progress) + matching anti-pattern; plus a task-prompt fix (it wrongly told the agent to use insert_line, contradicting HARD RULE 3 — now annotate_trace/annotate-once). All general, not benchmark-specific. It flipped 5 thrash-failures to pass by killing the restore-loop; the 2 still-failing cases weren't thrash cases (genuine difficulty). Retention tuning moved cost; the prompt fix moved accuracy.
Regression gate + promotion. converge on fastapi+spring+vulnyapi = 11/12, identical per-case to v7, 0 regressions (clean cases never thrash → commit-discipline is a no-op there). Promoted active: v7 → converge (commit 51f40bb), 1038 unit tests pass. Best production config: converge + byte-budget ON (accuracy + cost). New eval infra shipped this session: dated per-run archive / data-loss fix (3d80ae0), FS_HEAVY_KEEP_LAST_N knob (dbf7c8b), trace pass@N loop (3ede881).

4 · Cross-cutting conclusions

  • Detection (small model): precision needs a semantic verifier, not structural filters; recall must be earned by verification, not stricter prompts. The single biggest measurement insight is that the eval itself under-counts — GT-completeness (G3-1) is a prerequisite for trusting precision deltas.
  • Trace (47 cases run, 36 pass): strong on small/medium fixtures (vulnyapi 10/10, community 5/6, identity 13/14) but recall collapses on the large Django service (workshop 7/15, 7 complete-miss BOLA/injection/missing-auth cases) — the priority weakness (first trace run on workshop; no prior baseline). Two failure modes: (A) over-annotation of the full auth/JWT chain (precision fails that GT likely under-credits) and (B) genuine misses on large codebases. Cost scales hard: large real-world services cost ~6× per case and are exactly where recall breaks.
  • Cost ceiling: the 47 trace cases consumed ~14.4M tokens total; the 35 crApi cases alone were 12.3M / 1h46m — large-service evals are the dominant GPU cost and the real test of the approach.
  • Levers shipped: QW1/QW3/QW4/QW7/QW8 merged to main (all default-off, review-verified, 5 low findings fixed). QW3 promoted to SAFE/WIN after the controlled pass@3.

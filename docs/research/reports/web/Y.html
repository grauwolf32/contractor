Y · BFS × DFS discovery duality

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

Y1 — BFS and DFS find largely disjoint bug sets; union recall ≫ either alone

Argus: Reorchestrating Static Analysis via a Multi-Agent Ensemble for Full-Chain Security Vulnerability Detection
Multi-agent ensemble explicitly composes complementary analysis stages (pattern detection + full-chain dataflow tracing) — direct evidence that shallow-pattern and deep-chain detectors cover different bug populations and benefit from union.
llm-sast-scanner — structured SAST skill across 34 vulnerability classes
A SAST skill that combines broad per-class pattern scanning with source-to-sink taint tracing; a concrete reference for measuring overlap between the pattern (BFS) layer and the taint (DFS) layer per class.
Multi-Agent Taint Specification Extraction for Vulnerability Detection
Shows that pure taint (DFS) detection misses bugs whose source/sink specs are unknown, motivating a complementary broad scan to seed them — supports the disjoint-set thesis.

Y2 — BFS→DFS handoff (scan seeds trace targets) more token-efficient than DFS-everywhere

Multi-Agent Taint Specification Extraction (SemTaint)
SemTaint directs the LLM only to the unresolved calls that enable a source→sink flow rather than tracing everything — the canonical "narrow where expensive DFS looks" argument, validating the vuln_scan_trace design.
Sifting the Noise: LLM Agents in Vulnerability False-Positive Filtering
Comparative study of using a cheap first pass to triage candidates before expensive verification — frames the cost tradeoff of a two-stage (broad-then-deep) pipeline empirically.
Learning to Triage Taint Flows Reported by Dynamic Program Analysis
Triage-then-deepen pattern: a cheap classifier prioritizes which taint flows deserve deep analysis, quantifying the efficiency gain of a handoff over deep-everywhere.

Y3 — Adaptive scheduling (iterative-deepening / best-first) beats fixed BFS-then-DFS on recall@budget

Iterative deepening depth-first search (Wikipedia)
IDDFS mimics breadth-first node expansion via successive depth-bounded DFS — the canonical algorithm for "start broad, deepen selectively" that the adaptive scheduler proposes.
LiteSearch: Efficacious Tree Search for LLM
Dynamically allocates compute budget per node to balance exploitation vs exploration in LLM tree search — directly applicable to a recall@budget-optimizing vuln scheduler.
Agent searching in a tree and the optimality of iterative deepening
Classical AI result on when iterative deepening is optimal for a budget-bounded agent — theoretical grounding for choosing IDDFS/best-first over a fixed schedule.

Y4 — Required depth correlates with bug class; a class-aware router assigns the right mode

Broken Object Level Authorization in the Wild: An Empirical Taxonomy
Taxonomizes BOLA/IDOR into horizontal/vertical/blind variants from 100+ disclosures — a basis for stratifying which classes are shallow (router→BFS) vs need multi-hop reasoning (router→DFS).
Automatic Detection of Access Control Vulnerabilities via API
Detects missing-authorization (a BFS/absence-pattern-catchable class) at the API surface, illustrating that authz bugs need a different mode than taint-style chains — evidence for class→mode mapping.
Inferring Patterns for Taint-Style Vulnerabilities With Security Patches (IEEE)
Characterizes taint-style classes as inherently dataflow/DFS-oriented and pattern-incomplete, contrasting them with pattern-matchable classes — supports per-class routing.

Y5 — BFS most small-LLM-friendly; DFS depth needs graph-tool scaffolding to stay in-window

Lost in the Middle: How Language Models Use Long Contexts
Foundational evidence that models degrade sharply when relevant info sits mid-context — DFS's multi-hop path is exactly this hazard, justifying graph-tool scaffolding to keep DFS in-window.
Bridging Code Property Graphs and Language Models (Codebadger)
MCP server giving agents program-slicing/taint/dataflow tools so they navigate a CPG instead of reading whole files — the concrete scaffolding that lets small models do DFS without exhausting the window.
LLMxCPG: Context-Aware Vulnerability Detection Through CPG-Guided LLMs
Uses CPG slices to feed the LLM only the relevant inter-procedural path, shrinking peak context for deep analysis — measures the depth/context tradeoff that Y5 predicts widens for small models.
Context Discipline and Performance Correlation under Varying Context Lengths
Quantifies quality degradation as context grows, with the effect larger on weaker models — directly supports a wider small↔large gap for the context-heavy DFS mode.

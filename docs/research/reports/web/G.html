Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

G1 — Adding sink/source patterns for an under-covered language lifts that language's recall

Semgrep Taint Mode docs (sources / sinks / sanitizers / propagators)
Canonical schema for per-language source/sink/sanitizer specs; a ready vocabulary and worked examples to mine when authoring a Go/Rust sink reference markdown.
CodeQL 2.23.7/2.23.8 add security queries for Go and Rust (GitHub Changelog)
Names concrete Go/Rust sink queries (weak-crypto, insecure-cookie, weak-sensitive-data-hashing) — a curated, authoritative seed list for the under-covered-language sink refs.
semgrep-codeql: CodeQL security rules converted to Semgrep format (GitHub)
A pre-converted rule corpus; useful as a donor source of per-language source/sink patterns to distill into markdown skill refs.
Semgrep vs CodeQL 2026: SAST head-to-head (AppSec Santa)
Maps which languages have deep vs shallow framework/sink modeling in each tool — confirms Rust/Kotlin/Swift/Scala/Elixir are exactly the thin-coverage tier the project flags.

G2 — Adding an uncovered vuln class (race/TOCTOU, SSRF-to-cloud-metadata) surfaces an invisible finding class

CWE-367: Time-of-check Time-of-use (TOCTOU) Race Condition (MITRE)
Authoritative definition + examples + detection notes for TOCTOU; the source of truth for a new race-condition skill ref's sink/timing patterns.
CWE-362: Race Condition / improper synchronization (MITRE)
Broader concurrency-bug taxonomy beyond TOCTOU; ensures the new class covers shared-resource races, not just check-then-use.
From Generalist to Specialist: CWE-Specific Vulnerability Detection (arXiv)
Shows that targeting detection per-CWE class measurably moves recall for that class — direct evidence for the "0 TP → detected" test design.
The Hidden Dangers of Public Serverless Repositories (arXiv)
Empirical security assessment of cloud/serverless misconfig (IAM, metadata exposure) — grounds the SSRF-to-cloud-metadata and IaC class with real-world sink patterns.

G3 — Each added skill ref helps the 27b model more than the 70b (knowledge substitutes for capacity)

Software Vulnerability Detection Using LLM: Does Additional Information Help? (MIT/WAITI'24)
Directly tests whether injecting extra context/knowledge changes detection, and how the effect varies by model — the closest published analog to the ref-on/off × model-size 2×2.
ReVul-CoT: RAG + Chain-of-Thought for Vulnerability Assessment (arXiv)
Shows retrieved CWE/CVE knowledge raises assessment accuracy by grounding rather than free-recall — the mechanism by which a markdown ref substitutes for model capacity.
Everything You Wanted to Know About LLM-based Vulnerability Detection (arXiv)
Synthesis of where LLMs fail at vuln detection and where external knowledge helps most; supports the hypothesis that smaller models gain disproportionately from injected sink knowledge.

G4 — Ad-hoc AST-pattern search (ast-grep) for syntactic shapes the call-graph can't resolve

ast-grep: CLI for code structural search/lint/rewrite (GitHub)
The exact tool the hypothesis names — tree-sitter-backed structural matching of expression shapes like os.system($CMD) or request.args[$K], a drop-in complement to the call graph.
ast-grep Core Concepts: Pattern syntax (docs)
Documents metavariables and isomorphic-to-code patterns — shows how to express attribute chains/subscripts/dynamic sink shapes structurally instead of with lossy regex.
Demystifying Taint Mode (Semgrep blog)
Explains why pattern/structural matching outperforms regex for sink discovery and how it composes with dataflow — motivates ast-grep as the structural layer beneath taint.
Comparing Semgrep and CodeQL (Doyensec)
Practitioner comparison of lightweight pattern matching vs full semantic analysis; frames the cost/benefit of a thin ast-grep wrapper vs a heavyweight engine for novel/obfuscated sinks.

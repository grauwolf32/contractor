AE · Prompt-surface architecture — the three deterministic layers

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

AE1 — Layer placement changes outcomes; establish routing rules empirically

Effective context engineering for AI agents (Anthropic)
Defines the discipline as "what the agent knows, sees, and remembers at the moment of action," with distinct roles for system prompt vs tools vs just-in-time retrieval — the canonical statement that where content lives changes behavior and cost, AE1's premise.
Context Engineering: From Prompts to Corporate Multi-Agent Architecture (arXiv)
Treats context placement across layers as an architectural design problem with measurable trade-offs — supports turning layer routing into an evidence-based rule rather than convention.
Context engineering vs. prompt engineering (Elasticsearch Labs)
Distinguishes persistent instruction (resident) from dynamically assembled context (per-task/on-demand) — frames the resident-vs-per-task-vs-lazy axis AE1 A/Bs.

AE2 — Minimal, focused layers help small LLMs disproportionately; bloat crowds the small window

The Impact of Prompt Bloat on LLM Output Quality (MLOps Community)
Documents reasoning degradation starting ~3000 tokens — far below the context max — so irrelevant resident text actively hurts accuracy/coherence; the core evidence that bloat is a real tax, heaviest where the window is tightest.
Why Long System Prompts Hurt Context Windows (and How to Fix It)
Explains instruction dilution and lost-in-the-middle for bloated system prompts, and the prefill/KV-cache cost — directly the always-resident agent-prompt penalty AE2 measures by model size.
Not All Needles Are Found: How Fact Distribution… Shape… Hallucination Risks in Long-Context LLMs (arXiv)
Empirical long-context study showing extraction/inference degrade as input grows and facts disperse — the mechanism by which a verbose prompt steals capacity a small model needs for the actual code.

AE3 — Fine-grained, lazily-pulled skills beat monolithic bundles for small LLMs

Equipping agents for the real world with Agent Skills (Anthropic)
Defines Skills' progressive disclosure: metadata → instructions → resources, "load information only as needed," no context penalty for unused bundled content — the exact design divergence AE3 validates (index + small refs vs monolith).
SkillReducer: Optimizing LLM Agent Skills for Token Efficiency (arXiv)
Directly studies skill token efficiency and the chunk-granularity trade-off (too fine = round-trips, too coarse = over-pull) AE3 names — the closest academic work to the fine-vs-monolithic head-to-head.
Agent Skills: The Architectural Shift from Mega-Prompts to Progressive Disclosure
Argues the monolithic mega-prompt era is "failing due to prohibitive token costs and performance degradation," replaced by a three-level tiered hierarchy — the industry framing of AE3's claim that tiered beats monolithic.

AE4 — The task-prompt worker-context channel is high-leverage for per-target grounding

Effective context engineering for AI agents (Anthropic)
Advocates retrieving per-task facts "just in time" rather than pre-loading everything into the system prompt — supports injecting per-target facts (endpoint under test, prior findings, AC observations) via the per-task channel, not the resident agent prompt.
Prompt Bloat: Causes, Costs & Fixes for LLM Apps (Redis)
Frames the cost difference between always-resident vs request-scoped context and how to keep per-request context tight — the resident-vs-per-task cost comparison AE4 measures.

AE5 — Placement-by-access-frequency minimizes tokens at equal quality

Progressive disclosure of agent tools from the perspective of CLI-tool style (claude-code-router)
Argues frequently-needed capabilities stay resident while rarely-needed ones are disclosed on demand — exactly the access-frequency cost model AE5 wants to formalize and audit placements against.
Progressive Disclosure in AI Agents: How to Load Context Without Killing Output Quality (MindStudio)
Operational rules for deciding what to keep resident vs fetch on demand to minimize tokens at held quality — a practical checklist for re-routing mis-placed items.

AE6 — A hard skill-injection cap per worker; the "everything agent" as anti-pattern

Writing effective tools for AI agents (Anthropic)
"Curate the minimal viable set of tools" — the same focus-beats-breadth principle behind capping how many skills a single worker loads (complements AA, bounds bloat at the source).
SkillReducer: Optimizing LLM Agent Skills for Token Efficiency (arXiv)
Quantifies the token cost of over-broad skill loading and the gains from bounding it — evidence basis for whether a 1–3 (max 5) cap holds or improves small-model F1/context.
Explore Integration of Agent Skills with Automatic Tool Management via Progressive Disclosure (agentscope issue)
Real implementation discussion of validating/limiting which skills a worker pulls — the comparative precedent (cf. Strix validate_requested_skills) for an enforced per-worker budget.

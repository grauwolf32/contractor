AF · Agent-loop control & convergence

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

AF1 — Near-duplicate (not exact-match) action detection that forces a strategy change

Why Does Your AI Agent Get Stuck in Infinite Loops? (Pithy Cyborg)
Spells out two detectors beyond byte-equality: hash tool-name+params (3 identical = loop) AND semantic convergence detection — >85% similarity between consecutive states triggers intervention. Directly the near-duplicate guard AF1 wants over the current exact-consecutive callback.
Why Your AI Agent Keeps Looping and How to Stop It (Meritshot)
Argues agents loop because nothing tells them cycling between states isn't progress; loop guardrails must be external, deterministic mechanisms that override the agent — the "computed in code, not model cleverness" premise of AF.
TIDE: Trajectory-based Diagnostic Evaluation of Test-Time Improvement in LLM Agents (arXiv)
Trajectory-level diagnosis of when test-time iteration stops helping vs grinds — a method for measuring whether a near-duplicate guard breaks XBEN-010-style non-convergence without tripping on legitimate refinement.

AF2 — Periodic injected self-critique improves recovery from stuck states

Building a Self-Correcting AI: Reflexion Agent with LangChain/LangGraph
Reflexion (Shinn et al., NeurIPS 2023) translates a failure/stuck signal into verbal self-critique ("I got stuck in a loop, try a different strategy") prepended to the next attempt — the canonical mechanism behind AF2's injected critique cadence.
Agent Self-Correction: From Reflexion to Process Reward Models (Zylos Research)
Reviews when periodic self-reflection helps vs adds cost, including PALADIN-style recovery training on failure trajectories — useful for tuning cadence so escape rate rises without a token blowup.
How Do Agents Learn from Their Own Mistakes? The Role of Reflection in AI (Hugging Face)
Survey of reflection patterns and their cost/benefit; the "am I looping? is this impossible?" critique AF2 proposes is a scheduled instance of the reflection pattern.

AF3 — "New-situation" re-plan gate (re-plan only when facts/blockers materially changed)

Plan commitment: Replanning versus plan repair (Engineering Applications of AI, ScienceDirect)
Studies plan commitment — when to fully replan vs repair vs do nothing — the academic core of AF3's gate: trigger re-derivation only on material change, not on every intent addition.
How to Implement Agent Planning (OneUptime)
States the practical rule: replan when the agent uncovers new information that changes scope — be selective to avoid wasteful replanning; the firing condition AF3 codifies.
Planner Agent Explained: How Alhena AI Routes Every Request
Concrete production planner that explicitly does NOT replan to "correct" an answer (cf. Cairn) — replanning is about routing on changed state, reducing churn while holding quality.

AF4 — "Did nothing" / empty observations as a diagnostic on malformed subtasks

Why Does Your AI Agent Get Stuck in Infinite Loops? (Pithy Cyborg)
Time-per-step and no-progress signals distinguish "working but slow" from "stuck doing nothing" — supports surfacing empty observations so the planner can tell confused-but-working from dead.
Failure Modes in LLM Systems: A System-Level Taxonomy for Reliable AI Applications (arXiv)
System-level taxonomy that separates "produced output but did no real work" from other failures — the diagnostic distinction AF4 wants to route on (malformed-AND-empty vs malformed-but-active).

AF5 — Vendor the primitive: ship encoders/payload-builders as tools, not hand-derived algorithms

Bypassing XSS Filters With JSFuck: A Pentester's Creative Exploit (Undercode Testing)
Describes JSFuck (six-char JS obfuscation) as a pentest primitive — the exact construction XBEN-010 stalled hand-deriving; ships better as a callable encoder than as prose the model rebuilds recursively.
XSS-LOADER: Xss Payload Generator / Scanner (GitHub)
An existing, packageable payload/encoder generator — concrete prior art for vendoring an executable encoder asset rather than asking a small model to construct one.
Agent Self-Correction: From Reflexion to Process Reward Models (Zylos Research)
Notes small/weaker models are far better at calling a provided primitive than executing long mechanical derivations — the general principle (AA3/E4 case) that justifies vendoring the encoder to sidestep the derivation loop.

AL · Iterative solution-space exploration (memory-carrying re-planning)

Treating the planner's min_iterations/max_iterations loop as a stateful, memory-carrying search over solution paths — not mere retry. Conceptually a two-level search: depth-first within one iteration (commit to a plan, expand its subtasks) and breadth across iterations (try alternative whole-plan strategies, informed by accumulated memory) — distinct from Direction Y, which searches the codebase, not the plan space. Links are real web-search results; relevance notes are the researcher's synthesis.

AL1 — more iterations raise coverage on multi-solution tasks

Large Language Monkeys: Scaling Inference Compute with Repeated Sampling
Coverage — fraction of problems solved by any attempt — scales log-linearly with the number of attempts (SWE-bench Lite 15.9%→56% over 250 samples). Direct evidence that a min_iterations>1 budget converts into solved cases when a verifier can pick the win.

AL2 — memory-carryover across iterations beats memoryless re-runs

Reflexion: Language Agents with Verbal Reinforcement Learning (NeurIPS 2023)
Agents keep reflective text in an episodic memory buffer and use it to make better decisions on the next trial — improving without weight updates. This is exactly "each iteration reviews prior memories/records to choose a better path"; the persistence is what makes iterations cumulative rather than independent re-rolls.

AL3 — explore vs exploit: balance branching to a new path against continuing/deepening the prior one

Tree of Thoughts: Deliberate Problem Solving with LLMs
Explicitly explores multiple reasoning paths with lookahead and backtracking, navigated by a search algorithm (DFS/BFS/beam). Game-of-24 jumps from 4% (single CoT path) to 74% with deliberate branching — evidence that structured exploration beats hoping the model varies on its own (the "may or may not re-path" gap).
Language Agent Tree Search (LATS, ICML 2024)
MCTS over agent states (action history + observations) with LM value functions and self-reflection; 92.7% pass@1 on HumanEval. MCTS/UCT is the explore-vs-exploit balance — sometimes it deepens a promising node, sometimes it branches — which is exactly the "continue vs switch path" decision the planner faces each iteration.

AL4 — the exploration strategy belongs in the task config (different tasks want different search)

Tree of Thoughts (search algorithm is a parameter)
ToT treats the search algorithm (DFS vs BFS vs beam) and breadth/depth as explicit, task-dependent parameters — supporting the author's instinct that the strategy (explore/exploit/diversify, min/max_iter) should be declared per task, not a single global setting.
LATS (configurable tree-search budget)
LATS's branching factor and rollout budget are tunable knobs — the analogue of declaring per-task iteration/exploration budgets, so cheap tasks stop early and hard tasks get depth.

AL5 — cap iterations by value-of-information, not a flat number

Large Language Monkeys (diminishing returns)
Coverage gains follow an exponentiated power law and verification/voting methods plateau after a few hundred samples — so a flat max_iterations over- or under-spends; stop when marginal new-finding probability falls below a threshold (ties Direction U).

AL6 — persisted memory can entrench errors; record refuted paths

Reflexion (memory shapes later trials)
Because reflective memory steers subsequent trials, a wrong reflection persisted across iterations can mislead later ones — the run-to-run persistence cuts both ways. Mitigation: store refuted paths (not just explored ones) so the search doesn't re-enter or entrench a dead end. Connects to the cascade / false-consensus risk in Direction AH.

AL7 — search topology: breadth-over-plans × depth-in-run; make it explicit best-first/beam

Tree of Thoughts (DFS / BFS / beam are explicit)
ToT makes the search algorithm a parameter over a tree of partial solutions with a value heuristic. "One complete plan per iteration, try another next time" is breadth at the root; ToT shows you can instead expand the most promising partial (best-first/beam) rather than re-attempt blindly — the principled upgrade of the iteration loop.
LATS (explicit search tree + value-guided frontier)
Models solving as a search tree (nodes = state, edges = actions) navigated by MCTS — a principled "which plan/branch to expand next," replacing implicit iterate-and-hope with a value-guided frontier; the formal version of the planner's across-iteration breadth.

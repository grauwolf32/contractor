X · Well-known formats as the reasoning substrate

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

X1 — Generating an OpenAPI spec first improves endpoint-vuln recall / fuzz targeting vs raw source

Automatic Detection of Access-Control Vulnerabilities via API Specification Processing (arXiv 2201.10833)
Shows that reasoning over the API spec (the complete endpoint/parameter map) surfaces access-control bugs that piecemeal source reading misses — direct evidence the spec-as-map lifts endpoint-vuln recall.
API Fuzz Testing: Techniques, Tools, and Best Practices (StackHawk)
Explains that schema-aware (generation-based) fuzzing reaches more semantically meaningful code paths than blind mutation — the mechanism by which an OAS artifact improves fuzz targeting.
You Can REST Now: Automated REST API Documentation & Testing via LLM-Assisted Mutations (arXiv 2402.05102)
LLM reconstructs/uses an API schema to drive testing and beats source-only baselines on valid-input generation and coverage — supports the with-OAS vs without-OAS A/B.
OpenAI for OpenAPI: Automated Generation of REST API Specification via LLMs (arXiv 2601.12735)
LLMs transform source into OpenAPI capturing endpoints, validation rules, auth and error handling — the exact oas_build step, with framework-specific pattern recognition; validates that the generated spec is faithful enough to reason over.

X2 — A LikeC4 / architecture model improves threat-model quality (STRIDE coverage)

ThreatModeling-LLM: Automating Threat Modeling using LLMs for Banking Systems (arXiv 2411.17058)
Drives STRIDE analysis from a structured architecture/DFD representation and measures category coverage — the most direct prior art for "architecture model present vs absent → STRIDE recall".
ASTRIDE: A Security Threat Modeling Platform for Agentic-AI Applications (arXiv 2512.04785)
Diagram-driven, end-to-end STRIDE from architecture diagrams/DFDs — demonstrates that a standard architecture model (trust boundaries, dataflows) is what lets the model reason about threats it would otherwise reconstruct.
STRIDE-GPT (GitHub)
Working open-source tool generating STRIDE threat models from a structured app description with dataflows and trust boundaries — a reference implementation and a baseline to A/B LikeC4 against.

X3 — Emitting findings as SARIF beats bespoke free-text on reuse, interop, and small-model parsing

ZeroFalse: Improving Precision in Static Analysis with LLMs (arXiv 2510.02534)
Uses SARIF as the structured interface between static analyzers and LLM adjudication, preserving source-to-sink dataflow chains — shows SARIF makes findings machine-reusable and re-checkable by downstream LLM/triage, exactly X3's reuse claim.
ATLANTIS: AI-Driven Threat Localization, Analysis, and Triage (arXiv 2509.14589)
Implements a SARIF-matching module that aligns external reports with internally found bugs, with the LLM making final validation calls — concrete evidence SARIF enables cross-tool interop and downstream triage accuracy.
The Complete Guide to SARIF: Standardizing Static Analysis Results (Sonar)
Documents SARIF as the de-facto standard with CWE mappings, severity, and source/sink dataflow fields ingested by CI/IDE/quality gates — the interop + tool-ingestion target X3 measures, and confirms it is a pretraining-prevalent format.

X4 — Format-competence asymmetry: standard formats help small models more than large

KG-LLM-Bench: Evaluating LLM Reasoning on Textualized Knowledge Graphs (arXiv 2504.07087)
Finds format choice (JSON vs YAML vs list-of-edges) materially changes reasoning accuracy and that the effect is model-dependent — supports measuring a standard-vs-bespoke uplift that varies with model size.
Evaluating Structured-Output Robustness of Small Language Models (arXiv 2507.01810)
Specifically isolates small models: format sensitivity is larger for them, JSON is most parseable, and targeted prompting closes the gap — direct evidence small models lean harder on familiar/standard formats than large ones.
Let Me Speak Freely? Impact of Format Restrictions on LLM Performance (arXiv 2408.02442)
Important nuance / partial kill: forcing a structured format can hurt reasoning, and the cost differs by model — small models sometimes do better with narrative text. Tempers X4: "standard format" helps when it matches pretraining, not unconditionally.

X5 — Standard formats with mature automation let Contractor offload work (OpenAPI→fuzzers, SARIF→CI, HAR→replay)

RESTler: Stateful REST API Fuzzer (Microsoft, GitHub)
Consumes an OpenAPI spec, infers producer-consumer dependencies and finds security/reliability bugs via chained sequences — the off-the-shelf grinder Contractor's generated OAS can seed at near-zero marginal LLM cost.
Open Problems in Fuzzing RESTful APIs: A Comparison of Tools (ACM TOSEM)
Independent evaluation: Schemathesis found 1.4-4.5x more unique defects than the next-best fuzzer on real APIs — quantifies the external TPs a standard OpenAPI artifact unlocks (the X5 metric).
Deriving Semantics-Aware Fuzzers from Web API Schemas (Schemathesis paper, arXiv 2112.10328)
Shows a battle-tested fuzzer derived directly from the OpenAPI/GraphQL schema — the "model produces the spec, mature tool does the grinding" interface X5 proposes, with measured defect yield.
Schemathesis — Property-Based API Testing for OpenAPI/GraphQL
Drop-in tool that turns Contractor's OAS into systematic constraint-violating test generation — the concrete offload target to count bugs Contractor's own probing missed.

P · Adversarial self-play & synthetic fixtures

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

P1 — Recall on synthetic-injected vulns predicts recall on real held-out fixtures

LAVA: Large-scale Automated Vulnerability Addition (IEEE S&P 2016)
The canonical taint-driven bug-injection tool that makes labeled corpora to evaluate bug-finders. Crucially, its evaluation showed existing fuzzers/SA tools found only a small fraction of injected bugs — i.e. the synthetic-vs-real validity question is exactly the open problem P1 must test.
AVIATOR: AI-Agentic Vulnerability Injection Workflow for High-Fidelity Code Security Datasets
Recent (2025) agentic injection pipeline aimed at producing realistic labeled bugs at scale — direct prior art for the "generator" half of P and an argument that LLM-injected bugs can be made more realistic than template-based LAVA bugs.
LLMs Versus Static Code Analysis Tools: A Systematic Benchmark for Vulnerability Detection
Reports the recurring finding that detector rankings differ between synthetic and real-world benchmarks (comparable accuracy only on synthetic/single-project). This is the threat-to-validity P1 measures — synthetic recall may not transfer.
DiverseVul: A New Vulnerable Source Code Dataset
A large real-world labeled dataset usable as the "real held-out" leg of the correlation test, and documents label-noise/leakage issues that confound any synthetic-to-real correlation claim.

P2 — Iterating finder-vs-generator improves real-fixture recall, training-free

A Co-Evolving Attacker–Defender Adversarial Game for LLM Safety
Direct analogue of the finder-vs-generator loop: attacker discovers exploits, defender patches, incentives shift, attacker diversifies — the co-evolutionary signal P2 hopes to harness.
Chasing Moving Targets: Online Self-Play RL for Safer Language Models (Self-RedTeam)
Single model alternating attacker/defender roles with an adjudicator reward — shows the self-play curriculum is "self-improving" without external labels, the core P2 mechanism (though it uses RL, not P2's training-free framing).
DASE: Dual-Cycle Adversarial Self-Evolution (training-free)
Explicitly a training-free co-evolution framework — the closest precedent for P2's "no weight updates" claim, where improvement comes from prompt/experience updates rather than fine-tuning.
Multi-Agent Evolve: LLM Self-Improve through Co-evolution
Generalizes self-play beyond safety to task-solving co-evolution; useful evidence (and caveats on collapse/reward-hacking) for whether real recall actually climbs across rounds.

P3 — Injection difficulty can be tuned to model size (curriculum)

AutoCTF: Creating Diverse Pwnables via Automated Bug Injection (USENIX WOOT'17)
Builds on LAVA to inject bugs at controllable diversity/difficulty for CTF challenges — direct precedent that injected-bug difficulty is a tunable knob, supporting P3's curriculum framing.
panda-re/lava (LAVA implementation)
Maintained codebase whose "knob and trigger" magic-value mechanism literally parameterizes how rarely a bug fires — a ready lever for varying injected difficulty per model size.
EvilCoder: Automated Bug Insertion (ACSAC 2016)
Injects by removing safety checks from real vulnerable-but-guarded code via dataflow analysis; a different difficulty profile than LAVA (more realistic, harder), giving P3 two contrasting difficulty regimes to curriculum over.
Chaff Bugs: Deterring Attackers by Making Software Buggier
Studies controlling whether injected bugs are exploitable vs merely triggerable — relevant calibration concern: difficulty tuning must keep injected bugs genuinely detectable/exploitable, not degenerate.
Automated Customized Bug-Benchmark Generation
Framework for generating bug benchmarks with controllable characteristics/granularity — supports the idea of dialing injection parameters to produce a "learning-signal-per-token" curriculum.

N · Patch-diff & N-day variant hunting

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

N1 — Given a known fix + pattern, find ≥1 unpatched sibling occurrence

Trail of Bits — variant-analysis skill
A packaged agent skill for exactly N1: use a known vulnerability as a seed to find analogous unguarded sites. Concrete prior art for the extract-pattern→search-siblings loop, from a top security shop.
About CodeQL — variant analysis
The canonical engine: model one vulnerability as a query and it surfaces logical variants of the same class. Establishes variant hunting as a mature, semantic (not grep) discipline the agent can emulate or wrap.
Blackwing — Finding Vulnerability Variants at Scale
Practitioner methodology for generalizing a confirmed bug into a pattern and hunting siblings at scale — useful for defining variant-match precision and what counts as a true sibling.
Variant analysis of the 'Sequoia' bug
Worked example: from one patched bug to unpatched siblings in the same tree. A realistic fixture template for the patched+unpatched-coexisting test N1 calls for.

N2 — Diff-scoped review finds introduced vulns at a fraction of full-scan cost (CI-viable)

DRS-OSS: Practical Diff Risk Scoring with LLMs
Directly on N2: estimates how likely an individual diff is to introduce a defect, to prioritize/gate reviews and manage CI capacity — the diff-scoped, budget-bounded review N2 proposes, with risk scoring built in.
Datadog — Detecting malicious pull requests at scale with LLMs
Production diff-scoped LLM review; notably recursively breaks large diffs into chunks to preserve eval quality and signal-to-noise — a practical recipe for keeping per-PR token cost low.
GitHub Docs — Triaging code scanning alerts in pull requests
Reference for the diff-scoped UX: only alerts inside the PR diff are surfaced. Defines the per-PR scoping contract a CI-viable Contractor mode would target.
GitHub Blog — How to review agent pull requests
Recent guidance on reviewing changes scoped to a diff (including agent-authored ones) — context for where diff-scoped automated review is heading and what recall expectations are reasonable.

N3 — Cross-repo transplant: a pattern confirmed in A detects its analog in B

GitHub — Multi-repository variant analysis
Direct prior art for N3: run one query/pattern across many independent codebases at once to find the same flaw class elsewhere. Validates cross-repo transfer as a real, deployed capability.
What Is Variant Hunting in Security? A Deep Dive
Frames variant hunting as tracking a flaw pattern "across products, codebases, or architectures" — the conceptual basis for transplanting a pattern from project A to B rather than memorizing A.
DeepDiff — Binary Diffing for Vulnerability and Patch Detection
Cross-binary patch/vulnerability matching (binary analog of cross-repo transplant) — evidence the confirmed-pattern-to-new-target transfer generalizes even without shared source.

N4 — Git provenance tools (blame/log/show) as first-class; churn-priors improve recall@budget

Nagappan & Ball — Use of Relative Code Churn Measures to Predict System Defect Density
Canonical evidence for churn-priors: relative code churn discriminates fault-prone from clean binaries at ~89% accuracy. The empirical justification for prioritizing recently-/heavily-churned code in recall@small-budget.
Defect Prediction with Content-based Features
Recent defect-prediction work using code content + history features — supports building a churn/recency prior that feeds the value-of-information ordering N4 describes.
Origin — A Patch-Diffing Pipeline for N-Day Generation
End-to-end pipeline that uses commit/patch history to localize what changed and scope N-day work — concrete motivation for exposing git_blame/git_log/git_show as first-class tools to scope variant hunting.

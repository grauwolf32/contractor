AK · Automatic prompt / skill / task refinement

Closed-loop self-improvement of the harness artifacts (prompts, tasks, skills) from eval failures + traces + metrics. Links are real web-search results; relevance notes are the researcher's synthesis. The data-requirements question (AK7) is the most actionable part.

AK1 — reflective / textual-gradient refinement beats hand-tuning at lower effort

GEPA: Reflective Prompt Evolution Can Outperform Reinforcement Learning (ICLR 2026 oral)
An LLM reflects in natural language on its own trajectories — reasoning steps, tool usage, eval feedback — to diagnose failures and propose targeted prompt edits, combining lessons along a Pareto frontier. Beats MIPROv2 by >10% and GRPO with 35× fewer rollouts. The closest published match to "use analytical skills to refine prompts from failures."
Automatic Prompt Optimization with "Gradient Descent" and Beam Search (ProTeGi)
Generates "textual gradients" — natural-language descriptions of a prompt's flaws on sample data — then edits the prompt in the opposite semantic direction, guided by beam search. The mechanism for turning eval failures into prompt edits.
TextGrad: Automatic "Differentiation" via Text
Generalizes textual gradients into a PyTorch-like framework that can optimize any text variable (prompt, skill text, instructions) from downstream feedback — a reusable substrate for refining all three surfaces.

AK2 — failure attribution to the right surface is the missing (and hard) signal

Which Agent Causes Task Failures and When? Automated Failure Attribution of LLM Multi-Agent Systems
Defines failure attribution (who/when/why) and the Who&When dataset; crucially, the best automated method reaches only ~53.5% at naming the responsible agent and 14.2% at the step — so attributing an error to the right surface (agent-prompt vs task-prompt vs skill) is itself an open, non-trivial problem, not a free lookup. Sets realistic expectations for AK2.
A Comprehensive Survey of Self-Evolving AI Agents
Surveys the loop of observe → diagnose → edit for agentic systems; frames attribution + targeted update as the core of self-evolution and catalogs where current methods are weak.

AK3 — per-finding rationale / trajectory is required input the telemetry may lack

GEPA (reflection needs the trajectory)
GEPA's diagnosis depends on having the reasoning steps, tool calls, and detailed eval feedback to reflect over — i.e. a refiner needs the model's rationale per finding (why reported / why it stopped), not just the final label. If records don't capture rationale, the refiner is reflecting blind.
Who&When — failure logs include a "why" annotation
Their logs annotate who/when/why; the "why" is exactly the per-step rationale a refiner consumes. Confirms rationale capture is a deliberate data requirement.

AK4 — counterfactual pairs + a held-out split guard against overfit refinements

Prompt Overfitting
Optimized prompts can overfit training patterns and lose generalization — the central risk when auto-refining against a small eval set; ties to the project's anti-overfit principle (don't encode the benchmark's specific bugs).
Hyperband-based Bayesian Optimization for Black-box Prompt Selection
Notes a validation-optimal prompt may not be test-optimal, and too few validation instances make the val→test gap indistinguishable from noise — argues for proper splits and credible intervals when accepting a refinement.
GEPA in DeepEval — mutate on goldens, select on held-out
Practical recipe: prompts are mutated from feedback goldens but selected on held-out validation performance — the exact guard AK4 prescribes, ready to adopt.

AK5 — DSPy/MIPRO-style compile beats manual prompt-version authoring on the metric

MIPROv2 — DSPy optimizer
Jointly optimizes instructions and few-shot demos against your metric via a proposer model + Bayesian search over minibatches — "keeps what actually moves your metric." Directly applicable to optimizing the worker/planner instructions and any few-shot exemplars.
Large Language Models as Optimizers (OPRO)
Optimization by prompting: feed solution–score pairs back to an LLM that proposes better instructions; +8% on GSM8K and up to +50% on Big-Bench over human-designed prompts. The metric-in-the-loop instruction search at the heart of AK5.
DSPy (stanfordnlp) — framework
The program-compile abstraction (typed module + dataset + metric → optimized prompts) that makes refinement repeatable and version-controlled rather than ad-hoc.

AK6 — capture the maintainer's own edits as supervision

Self-Evolving AI Agents (survey)
Frames human-in-the-loop edits as a feedback source for self-evolution; the maintainer's past prompt/skill edits (and the metric delta each produced) are a cheap, high-signal supervision set to imitate or warm-start the auto-refiner. (No paper isolates "imitate the maintainer's prompt edits" specifically — a novel, testable angle here.)

AK7 — data-requirements audit: what an auto-refiner needs vs what's captured

GEPA / textual-gradient methods (required inputs)
Synthesizing what these methods consume: (1) labeled failures with the specific FP/FN — have (eval tp/fp/fn); (2) execution trace/records per case — have; (3) per-stage metrics/tokens — have; (4) deterministic observations (what was/wasn't touched, AC) — have; (5) per-finding rationale (why reported / why stopped) — likely missing (AK3); (6) error→surface attribution — missing (AK2); (7) counterfactual minimal pairs (same case, one surface changed) — not stored (the A/B harness can produce them); (8) prompt/skill version ↔ metric-delta linkage — partial; (9) held-out split + maintainer-edit history — partial/missing (AK4/AK6). The missing items (5,6,7,9) are the concrete telemetry to add.
MIPROv2 (needs: typed program + dataset + metric)
Confirms the minimum contract — a scored dataset and a metric the optimizer can call — which the eval harness already provides; the gap is the richer diagnostic signal (rationale + attribution), not the basic metric.

H · Automated dataflow / taint primitive

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

H1 — Intra-procedural def-use / taint primitive raises recall on taint bugs and cuts FPs on sanitized paths

Static Taint Flow Analysis (SonarSource)
Production definition of precise taint: report only when a source→sink path exists with no sufficient sanitizer — exactly the "model confirms instead of derives, sanitizers recognized" predicate H1 wants.
What Is Taint Analysis? (developer/researcher guide)
Clear primer on sources/sinks/sanitizers and def-use chains; covers which vuln classes (SQLi, cmdi, path traversal, XSS) taint catches — the test-fixture classes H1 names.
Semgrep Taint Mode (sanitizers/propagators) docs
Reference implementation of intra-procedural taint with explicit sanitizer modeling; a concrete design to emulate for the def-use-over-tree-sitter primitive.
You Shall Not Pass: Mitigating SQL Injection on Legacy Web Apps (arXiv)
Uses taint flow specifically against SQLi with sanitizer awareness; evidence that taint both finds true bugs and suppresses sanitized-path false positives.

H2 — Dataflow edges narrow the small↔large gap more than any prompt change

IRIS: LLM-Assisted Static Analysis for Detecting Security Vulnerabilities (arXiv)
Neuro-symbolic combo where the LLM mines taint specs and CodeQL does the dataflow propagation; shows offloading multi-hop propagation to a deterministic engine lifts detection — the core H2 mechanism.
Multi-Agent Taint Specification Extraction for Vulnerability Detection / SemTaint (arXiv)
"Static analysis as source of truth, LLM only where static under-approximates" — the explicit division of labor that removes multi-hop tracking from model working memory.
Argus: Multi-Agent Ensemble over Static Analysis for Full-Chain Detection (arXiv)
Orchestrates agents around static flow facts for full source-to-sink chains; relevant to whether deterministic edges close the capability gap on long chains.
No paper isolates the gap-closing effect by model size (27b vs 70b) specifically; IRIS/SemTaint establish the mechanism, the size-stratified test remains the project's own contribution.

H3 — Intra-procedural captures most benefit; inter-procedural adds marginal recall at high cost

How Interprocedural Data-flow Works in Joern (Joern blog)
Details the extra machinery (call-site summaries, over-approximation of unresolved methods) inter-procedural taint requires — concretizes the "high build cost" arm of the three-way test.
Scalable Language-Agnostic Taint Tracking using Explicit Data Dependencies (arXiv)
Studies the scalability/cost tradeoff of whole-program vs lighter taint; informs the recall-gain-per-build-cost comparison across none/intra/inter arms.
Taint Analysis Key Concepts (Qt/Axivion)
Lays out intra- vs inter-procedural tradeoffs and where each pays off; supports bounding engineering scope to intra-proc if it captures ≥70% of the gain.

H4 — Dominator-based control analysis: a guard counts only if it dominates the sink on every path

Cornell CS4120 Control-flow analysis lecture (dominators)
Formal definition: A dominates B iff every entry→B path includes A. The precise structural predicate that turns "is there a check?" into a mechanical "does the guard dominate the sink?".
Software Vulnerability Analysis Across Languages and Program Representations: A Survey (arXiv)
Surveys CFG/PDG/dominance-based detection of missing-check and missing-authorization bugs — situates the dominance predicate among established detection techniques.
What Is a Code Property Graph? (Apiiro)
CPG fuses AST+CFG+PDG so dominance/control questions become graph traversals; shows the representation on which the "guard dominates sink" check is naturally computed.
Joern data-flow internals (Joern blog)
Open-source CPG engine exposing control/data dependence edges queryably — a candidate substrate for implementing the dominance check without building dominators from scratch.

C · Exploit verification & dynamic confirmation

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

C1 — Requiring a request-id-backed proof chain (not self-asserted strings) reveals the true exploitation rate

Proof-of-Vulnerability (PoV) Test Execution (survey)
States the standard C1 wants to enforce: only concrete, reproducible exploits — not static oracles or theoretical traces — count as proof. The principle behind replacing a non-empty summary with a cited request-id chain as the evidence bar.
I Can't Believe It's Not a Valid Exploit (arXiv)
Documents how generated/asserted "exploits" frequently fail when actually validated — empirical motivation for C1's claim that tightening the evidence rule will expose a large gap between self-asserted and proven exploitation.
From CVE Entries to Verifiable Exploits: Multi-Agent CVE Reproduction (arXiv)
Builds verifiable, reproducible exploit evidence per CVE rather than accepting descriptions — a working model of the request-backed proof chain C1 proposes as the pass criterion.

C2 — Granting the exploit agent read-only code access raises verdict accuracy on sparse-seed findings

What Makes a Good LLM Agent for Real-world Penetration Testing? (arXiv)
Analyzes which information sources move pentest-agent success; relevant to C2's question of whether source-code grounding (vs black-box only) recovers entry points the seed omits, and the risk of "code-trusting" verdicts not backed by a probe.
Combining SAST/DAST/IAST for OWASP Top-Ten Detection (MDPI)
Shows white-box code context plus black-box testing detects more than either alone — supports granting targeted reads to the otherwise black-box exploit agent, while framing the precision tradeoff C2 must guard against.

C3 — One fused static+dynamic verifier beats the two split agents on verdict accuracy

Combining Static and Dynamic Analysis for Vulnerability Detection
Classic result: SA finds more but with FPs, DA confirms with precision; using SA to seed and DA to confirm raises detection and cuts false alarms — the exact join C3 argues the split trace-verify/exploit design loses.
Mitigating False Positives via RL over hybrid static-dynamic analysis (arXiv)
Frames "when is static evidence enough vs fire a dynamic check" as a single sequential policy — a principled basis for a fused verifier that decides per-finding whether to corroborate a path with a live probe, rather than two disjoint agents.
PoC-Adapt: Semantic-Aware Automated Vulnerability Reproduction (arXiv)
A multi-agent system fusing semantic (static) understanding with runtime validation and adaptive policy to confirm reproduction — a concrete architecture for the fused trace+probe verifier C3 proposes, with reported gains over staged pipelines.

C4 — XBEN-010 is solvable with an XSS execution oracle, not more time

HXD: Hybrid XSS detection using a headless browser (IEEE)
Shows HTTP-only reflection checks miss execution; rendering payloads in a real browser provides the success signal. Directly supports C4: the holdout loops because it lacks a DOM/JS execution oracle, not because it lacks time.
Using Headless Chrome to Detect XSS Vulnerabilities (Grio)
Concrete implementation: Puppeteer's page.on('dialog') as the alert oracle confirming script execution — a drop-in design for the headless-browser oracle C4 needs to give XBEN-010 a capture signal.
DOM XSS Active Scan Rule — OWASP ZAP
A maintained, open implementation of headless-browser DOM-XSS confirmation (Firefox/Chrome/Edge) — reusable prior art for wiring an execution oracle into Contractor's probing stack rather than building from scratch.

C5 — Per-finding exploit budgets (derived from metrics) cut XBOW total tokens without losing captures

AWE: Adaptive Agents for Dynamic Web Penetration Testing (arXiv)
Reports much better token-efficiency and speed than flat-budget agents (e.g. 87% XSS success) by adapting effort to the task — direct support that class-aware/adaptive budgets beat a flat per-finding allotment, the C5 thesis, even with a mid-tier model.
XBOW Benchmark: Autonomous Web Security Testing (overview)
Describes the XBOW task set and the time-to-solution / cost metrics used to compare agents — the measurement frame for C5's flat-vs-class-aware-budget comparison and what "captures held" means on this set.
Autonomous LLM Agents & CTFs: A Second Look (arXiv)
Critically re-examines CTF/capture metrics and per-task cost variance for LLM agents — useful for designing C5's budget experiment so capture counts are not confounded by easy-vs-hard task spread.

C6 — Bypass-exhaustion gate: require N distinct failed bypasses before any not_exploitable verdict

Detecting XSS and Checking for False Positives
Practitioner method showing a single failed payload is not evidence of safety — multiple varied bypass attempts are needed before declaring no-XSS. Concrete support for C6's explicit failed-bypass counter on negative verdicts.
SmartPoC: Generating Executable and Validated PoCs (arXiv)
Distinguishes "control genuinely withstood attempts" from "PoC merely not yet found" via executable validation — the same distinction C6 wants to encode so a negative verdict is earned by exhausted bypasses, not assumed.
Reflected XSS: Advanced Exploitation Guide — Intigriti
Catalogs the breadth of context-specific bypasses (filters, encodings, sinks) a tester must exhaust before concluding non-exploitable — gives a concrete basis for the "N distinct bypasses" threshold and what counts as distinct.

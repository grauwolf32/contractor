D · Simplification without capability loss

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

D1 — The four trace workflows collapse into one parametrized workflow with no eval regression

Automated Execution of Data Pipelines based on Configuration Files
Shows that expressing pipeline variants as configuration over generalized modules reduces duplication and improves maintainability "without sacrificing flexibility" — the exact D1 move of turning four near-identical workflows into config presets of one.
Durable Workflows in the Microsoft Agent Framework
Demonstrates a single workflow programming model that composes agents via wired executors/flags rather than separate hardcoded pipelines — a concrete pattern for a unified trace workflow parametrized by {driver, graph, path_parallel}.

D2 — Dropping the planner for single-iteration tasks (uniform AgentRunner) cuts LLM calls at equal completion

Building Effective Agents — Anthropic
The canonical "find the simplest solution; add agentic complexity only when simpler solutions fall short" guidance. Directly underwrites D2: for single-iteration tasks the planner's add/execute/finish loop is unwarranted overhead.
Single Agent vs Multi-Agent: When to Build (Towards Data Science)
Quantifies planner/multi-step overhead (chains can multiply cost/latency several-fold) and gives criteria for when a solo agent suffices — the decision rule for which tasks D2 should demote from planner to AgentRunner.
Agent system design patterns — Databricks
Catalogs workflow vs planner-executor vs autonomous-agent patterns and notes a single agent is often "slightly better than planner-executor" on straightforward tasks — supports measuring llm_calls/tokens drop at equal completion.

D3 — Unifying the vuln namespace eliminates the verify/pathpar coupling bug class

SARIF: a shared interchange schema between analysis stages
Illustrates why a single shared contract/namespace between producer and consumer stages prevents the drift D3 targets — when trace engines and the verifier agree on one schema/prefix, "can't consume pathpar output" coupling bugs disappear by construction.
Agent-Driven Pipeline: Modular AI Workflow (overview)
Describes wiring pipeline stages through a shared interface/contract so any compliant producer feeds any consumer — the design principle behind replacing the hardcoded trace-annotation: prefix with one shared namespace constant.

D4 — Dropping the records artifact + separate summarizer call reduces tokens/code with no downstream breakage

Effective Context Engineering for AI Agents — Anthropic
Argues for carrying the minimum high-signal context and avoiding redundant material that gets re-billed — supports D4's claim that an unconsumed records artifact plus a summarizer that re-bills the full payload is dead weight.
Dead Code Detection: Your Codebase Has More Than You Think
Methodology for proving an artifact/path is unconsumed before deletion (grep consumers, reachability) — the verification D4 needs ("no task declares /records") so removal is provably safe.

D5 — Pruning unwired agents / inactive prompts shrinks maintenance surface with zero eval impact

Axivion Dead Code Analysis (reachability on the call relation)
Documents reachability analysis over the call graph to find dead functions — the exact technique D5 prescribes (confirm web_exploitability_agent/threat_model_agent are unreachable from get_workflows()) before archiving.
What Is Dead Code? A Practical Guide for Engineering Leaders
Frames unused-but-valid code as silent technical debt weakening maintainability — the cost case for D5, and a checklist for safe removal (static reachability + behavior-identical regression test).
Dead Code Identification, Elimination, and Empirical Assessment (arXiv)
Empirically measures the maintenance/size benefit of eliminating dead code with no behavioral change — supports D5's pass criterion of "eval envelope byte-identical after removal."

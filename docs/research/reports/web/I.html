I · Graph-tool robustness

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

I1 — Quantify the dependency: with graph tools disabled, recall drops by a measurable margin

On the Recall of Static Call Graph Construction in Practice (ICSE'20, ACM)
Headline source: median call-graph recall ~0.884, i.e. ~11% of reachable methods missed; quantifies what graph navigation buys and what is silently lost when it degrades to grep.
Empirical study of LLMs for type and call-graph analysis in Python/JS (EMSE)
Measures how LLM-only reasoning compares to explicit call-graph tooling for resolution tasks — the on/off comparison this hypothesis runs, at the capability level.
Codebase-Memory: Tree-Sitter-Based Knowledge Graphs for LLM Code Exploration via MCP (arXiv)
Shows recall/exploration gains from giving an LLM a structured code graph vs raw text — supports that disabling the graph measurably hurts recall.

I2 — Building the graph from an overlay/remote snapshot recovers local-FS recall

On the Recall of Static Call Graph Construction (full PDF, ICSE'20)
Documents how missing/unmodelled code (the remote/overlay-partial case) drives recall loss; materializing a complete snapshot before graph build is the fix to recover the lost edges.
ACER: An AST-based Call Graph Generator Framework (arXiv)
Builds call graphs purely from ASTs (no compilation), so it can run over a fetched file snapshot — a design pattern for making graph tools work off GitLabFS/overlay backends.
Building a call-graph tool with tree-sitter in Python (Volito)
Concrete tree-sitter call-graph extraction that reads file bytes through an abstraction layer — illustrates porting graph construction to read via the FS abstraction rather than the local disk.

I3 — Surfacing skipped (non-UTF8 / unparsed) files recovers findings in repos that contain them

tree-sitter issue #285: error recovery / partial parse (GitHub)
Confirms tree-sitter emits ERROR/MISSING nodes rather than failing, and how unparsed regions silently drop nodes — the mechanism behind dropped graph nodes I3 wants to surface.
Is tree-sitter good enough? — limitations (Jake Zimmerman)
Catalogs where tree-sitter quietly mis/under-parses; argues for logging/exposing parse failures rather than dropping them — the minimum-viable fix in I3.
Modern Tree-sitter, part 7: pain points and the promise (Pulsar)
Practitioner deep-dive on error-recovery edge cases and encoding assumptions (UTF-8 expected); informs decode-fallback handling for non-UTF8 files so their nodes re-enter the graph.

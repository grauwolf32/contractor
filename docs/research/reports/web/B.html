B · Detection recall & precision

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

B1 — Activating the shannon (coverage-ledger / sink-slot) trace prompt raises recall at equal precision

IRIS: LLM-Assisted Static Analysis for Detecting Security Vulnerabilities (arXiv)
Pairs an LLM with a structured source/sink/taint scaffold and finds 28 more vulns than CodeQL without precision loss — direct evidence that forcing the model to reason over a sink inventory (the shannon coverage-ledger idea) raises recall at flat precision.
Benchmarking LLMs and LLM-based Agents in Practical Vulnerability Detection (ACL 2025)
Evaluates prompting/agent strategies on real-world detection; quantifies how methodology-structured prompting shifts the recall/precision frontier — useful for setting the +10%-recall-at-flat-precision pass/kill bar.
LLMs Versus Static Code Analysis Tools: A Systematic Benchmark (arXiv)
Finds LLM scanners' F1 advantage over SAST comes specifically from superior recall (reasoning across broader context), and that CoT-style prompting trades recall for precision — calibrates the expected direction of a coverage-forcing prompt change.

B2 — A structured finding schema (cwe/sink_kind/entry_point/data_flow) improves dedup precision and stops overwrite loss

The complete guide to SARIF — Sonar
SARIF is the standard structured finding schema: typed CWE id, physical location, flow-sensitive annotations, confidence. Adopting its field model (vs free-text details) is the concrete realization of B2 and enables principled merge keys.
SARIF limitations in security tooling — BoostSecurity
Documents that reliable dedup requires fingerprinting by rule id + physical location, and where SARIF still falls short — important caveat for B2's merge-on-structured-keys claim (string-split on "CWE-" is exactly the brittle approach this warns against).
ZeroFalse: Improving Precision in Static Analysis with LLMs (arXiv)
Treats each finding as a structured contract enriched with flow annotations and CWE-specific knowledge before LLM analysis — demonstrates that a typed sink/flow schema (not prose) materially improves precision, the core B2 prediction.

B3 — A second independent trace pass + programmatic union/dedup raises recall (single-pass is the constraint)

Multi-role Consensus through LLM Discussions for Vulnerability Detection (arXiv)
Reports an 18.25% recall increase from running multiple independent LLM perspectives and aggregating — direct support that misses are partly stochastic and recoverable by a second pass with union/dedup, the B3 hypothesis.
Self-Consistency Sampling in LLMs (survey)
Explains parallel multi-sample aggregation; notes parallel scaling maintains or improves recall (avoids the "overthinking conservatism" of sequential scaling) — the mechanism behind B3's union-of-passes and a caution on how to aggregate.
Reliability-Aware Adaptive Self-Consistency for Efficient Sampling (arXiv)
Shows how to spend extra passes adaptively rather than a flat N — relevant to B3's recall-vs-token-cost plot, letting easy cases stop early while hard cases get more passes.

B4 — Replacing hardcoded patterns with general methodology holds seen-fixture recall while raising held-out recall

eyeballvul: a future-proof benchmark for vulnerability detection in the wild (arXiv)
The exact held-out corpus B4/F3 propose to wire in: 24k+ real vulns across 6k+ revisions, refreshed weekly from new CVEs so it resists train/prompt contamination — the cleanest way to measure seen-vs-held-out generalization of a methodology prompt.
LLMs are Like a Chameleon: surface-cue overfitting (arXiv)
Shows models implicitly overfit to benchmark surface patterns, with performance dropping when cues are perturbed — the general statement of B4's overfit hypothesis (literal grep/WordPress patterns inflate seen recall, transfer poorly).
The Vulnerability of LM Benchmarks / held-out vs standard eval gap
Reports standard eval can overestimate by 8+ points versus held-out — quantitative motivation for B4's seen/held-out split and a sanity baseline for how large the overfit gap might be.

B5 — A SAST pre-pass (semgrep) seeding candidate sinks lets a 27b model match a 70b baseline's recall

SAST-Genius: A Hybrid Static Analysis Framework (LLM + Semgrep/CodeQL) (arXiv)
Integrates Semgrep/CodeQL findings as leads into an LLM triage layer, reporting up to 2.5× detection rate and up to 91% fewer false positives — strong evidence that seeding deterministic candidate sinks lifts recall while controlling the FP risk B5 flags.
SemTaint: Multi-Agent Taint Specification Extraction (arXiv)
Combines static taint sources/sinks with LLM agents (Source/Sink, CallGraph, Flow-Summary) to do what neither does alone — a blueprint for feeding ranked candidate sinks to the trace agent and offloading pattern-recall to an engine, the B5/E1 mechanism.
Semgrep vs CodeQL (2026): technical comparison
Practical comparison of the two candidate pre-pass engines (rule cost, language coverage, semantic depth) — informs which SAST engine to wire as the seeding pass and the precision/noise tradeoff that gates B5's pass/kill.

AB1 — Define & instrument hypothesis quality (hit-rate, hypothesis-recall, confirmed-per-token)

HypoSpace: Evaluating LLM Creativity as Set-Valued Hypothesis Generators under Underdetermination
Proposes metrics for a generator's set of hypotheses (validity, coverage of the admissible space) — directly informs hit-rate and hypothesis-recall as the instrument AB1 needs.
Prompting the Priorities: Evaluating LLMs for Vulnerability Triage and Prioritization
Defines hit-rate-style and prioritization metrics for LLM-emitted vuln judgments — a template for confirmed/generated and ranking-quality measurement.
Towards Explainable Vulnerability Detection with LLMs
Tackles the open problem of scoring vulnerability explanations; relevant to making "is this hypothesis evidence-grounded and falsifiable" a measurable quantity.

AB2 — Mode richness trades off: whitebox > graybox > blackbox on hit-rate; blackbox wins breadth-per-token

API Pentesting Methodology: black-box, grey-box, and white-box
Practitioner framing of the exact three modes and what signal each adds — grounds the precision-vs-reach tradeoff AB2 wants to quantify.
Is It Still Black Box If They Give You an API Spec?
Argues an OpenAPI spec shifts an engagement from black-box toward gray-box — clarifies where oas_analyzer sits on the mode spectrum and what extra signal moves it up.
LLMs Cannot Reliably Identify and Reason About Security Vulnerabilities (Yet?)
Comprehensive eval showing reasoning quality scales with available internal signal/context — supports the whitebox>graybox>blackbox hit-rate ordering hypothesis.

AB3 — Differential/comparative generation (the outlier sibling) beats per-endpoint spec-shape

Automatic Detection of Access Control Vulnerabilities via API Specification Processing
Infers expected authorization from the API spec and flags endpoints that deviate from their siblings — the formalized "siblings check ownership, C doesn't" signal AB3 proposes.
Detecting anomalies in access control lists (patent)
Extracts a policy from peers and flags object/group-level anomalies statistically — a differential/anomaly-from-siblings detector, transferable to endpoint authz comparison.
Enhancing REST API Fuzzing with Access Policy Violation Checks
Defines oracles requiring two users/roles to catch BOLA/BFLA, exactly where naming-based guesses fail — supports differential hypotheses cutting naming-based false positives.

AB4 — Active/behavioral generation (probe → observe differential → hypothesize) surfaces what static misses

Automated Black-box Testing of Mass-Assignment Vulnerabilities in RESTful APIs (ICSE 2023)
Sends calibrated requests and mines response differentials to detect mass-assignment from behavior alone — the canonical "probe, observe, hypothesize from anomaly" loop AB4 describes.
WuppieFuzz: Coverage-Guided, Stateful REST API Fuzzing
Drives the API from the OpenAPI spec and uses observed responses/coverage as feedback to find behavior-only bugs — a behavioral generator that static spec analysis cannot reproduce.
FuzzingBrain V2: Multi-Agent LLM System for Automated Vulnerability Discovery
Combines static structure with dynamic execution feedback to verify hypotheses — evidence that runtime probing yields a hypothesis class static analysis misses.

AB5 — Multi-modal fusion (OAS + arch + dataflow + traces) beats any single source

FuSEVul: Fusing code semantics with LLM-generated explanations
Self-attention fusion of code semantics and risk-aware NL descriptions beats 18 baselines (+52% F1) — direct support that fusing modalities outperforms single-source generation.
Fisher-Guided Adaptive Multimodal Fusion for Vulnerability Detection
Adaptively weights modalities (code structure, dataflow, metrics) for detection — a method for fusing OAS/LikeC4/dataflow/trace signals without one drowning the others.
Vulnerability Detection Based on Joint Graph and Multimodal Feature Fusion
Builds a joint graph from control/data/jump flow for fused feature extraction — analogue of fusing architecture (trust boundaries) with dataflow (reachability).

AB6 — Generate-then-critique (adversarial pruning before probe budget) raises efficiency

The Lighthouse of Language: Enhancing LLM Agents via Critique-Guided Improvement
A critic grades candidate actions and emits actionable suggestions — the over-generate-then-critique loop AB6 wants before spending verification probes.
Self-Generated Critiques Boost Reward Modeling (Critic-RM)
Generates many critiques then consistency-filters noisy ones — a concrete pruning mechanism for low-prior / non-falsifiable hypotheses.
Small Language Models Need Strong Verifiers to Self-Correct Reasoning
Critical caveat for 27b–80b models: small models' self-critique is unreliable without a strong verifier — directly bears on whether the AB6 critic stage helps or hurts at this scale.

AB7 — Hypothesis-as-typed-artifact (probe + oracle + prior + falsification) ranked by budget improves recall@budget

Hound: Relation-First Knowledge Graphs for Security Audits
Stores hypotheses as typed objects with confidence/status linked to evidence and triages them with the budget — the structured-and-ranked leads pool AB7 (and Z3) propose.
Prompting the Priorities: LLMs for Vulnerability Triage and Prioritization
Evaluates whether LLM priors/severity rankings track true confirmation — the prior-vs-confirmation calibration AB7 measures for recall@budget.
HypoSpace: set-valued hypothesis generators
Treats hypotheses as a structured, scorable set under underdetermination — supports making each hypothesis a typed, rankable artifact rather than prose.

AB8 — Diversity-controlled generation (cover classes/endpoints/assets) beats greedy single-class

Verbalized Sampling: How to Mitigate Mode Collapse and Unlock LLM Diversity
Prompts for a distribution of responses to restore diversity — a low-cost lever to stop a generator over-producing one vuln class and missing the real bug.
Quality-Diversity Evolution for Discovering Diverse Vulnerabilities in LLM Safety
Uses MAP-Elites to maintain a diverse archive across behavioral dimensions, explicitly combating attacker-side mode collapse — a method for enforcing spread across classes/endpoints/assets.
Escaping Mode Collapse in LLM Generation via Geometric Regulation
Characterizes hypothesis-generation mode collapse (converging on a limited subset despite validity) and a fix — the mechanism behind greedy generators' low hypothesis-recall.

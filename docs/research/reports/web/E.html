E · Elevating small LLMs (the north star)

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

E1 — Each unit of reasoning offloaded to a deterministic tool narrows the 27b↔70b recall gap

On the Tool Manipulation Capability of Open-source LLMs (arXiv)
Shows open/small models gain disproportionately from tool access on tasks where free-recall is the bottleneck — the core E1 asymmetry (offload helps the weaker model more), and how to make small models reliable tool users.
Small Language Models are the Future of Agentic AI (arXiv)
Argues that with the right tool/scaffold decomposition, small models match large ones on agentic subtasks — the strategic case for Contractor's mission and for measuring uplift as a function of how much reasoning is offloaded.
SemTaint: Multi-Agent Taint Specification Extraction (arXiv)
Concrete offload: deterministic taint sources/sinks/call-edges feed the LLM the dataflow it would otherwise have to recall — the kind of "deterministic lead" E1 wants to add and measure the gap-narrowing of.

E2 — Forced structured-output schemas cut small-model format failure more than large-model

Structured outputs with Amazon Nova (constrained decoding)
Reports constrained decoding cuts tool-use errors by 95%+ and notes "format fidelity often dominates prose quality" for agent stacks — direct support that schema enforcement attacks exactly the malformed/incomplete subtask rate E2 targets.
Generating Structured Outputs from LMs: Benchmark and Studies (arXiv)
Benchmarks grammar/JSON-schema-guided decoding across model sizes — the data to test E2's asymmetry claim (smaller models, which drift more, recover more from enforcement) and the caveat that valid structure ≠ correct values.
Guided Decoding Performance on vLLM and SGLang
Practical implementation of grammar/JSON-schema constrained decoding in the self-hostable serving stack Contractor targets (vLLM/SGLang via Outlines/XGrammar) — how to actually force schemas on local small models.

E3 — An "attack-surface + control-diff" tool lets small models do absence-detection they currently miss

Detecting BOLA Vulnerabilities in Database-Backed Applications — BolaRay (CCS 2024)
Static tool that infers per-object authorization models and flags handlers missing the expected check — found 193 true BOLAs (178 new) at 21.9% FP. The deterministic "diff the guards across sibling handlers" engine E3 proposes, doing the bookkeeping small models can't hold.
Automatic detection of access-control vulnerabilities via API specification processing (arXiv)
Detects IDOR/BOLA by comparing endpoints against their API spec to find missing authorization — a lighter-weight control-diff approach that pairs naturally with Contractor's attack_surface entrypoint enumeration.
Rethinking BOLA Attacks Under the Zero Trust Principle (arXiv)
Formalizes what "missing object-level authorization" means relative to sibling handlers — the model E3 needs so a control-diff tool knows which absent guard constitutes a finding (calibrating recall on BOLA/BFLA cases).

E4 — A payload/PoC library exposed as a tool beats payloads-as-prose for small-model exploit success

Hacking, The Lazy Way: LLM Augmented Pentesting (arXiv)
Builds a RAG index of Metasploit/MSFVenom modules, payloads and usage so the agent retrieves exact command syntax instead of recalling it — the direct realization of E4, motivated by exactly the free-recall weakness of smaller models.
CyberRAG: An Agentic RAG attack classification and reporting tool (arXiv)
Agentic RAG over a payload/attack knowledge base (ChromaDB + payload embeddings + metadata) queried by class — a working architecture for exposing per-class payloads as a queryable tool rather than skill prose.
The Best Open-Source LLMs in 2026 (recall-vs-retrieval framing)
Surveys current open-weight models and the general finding that retrieval supplements weaker parametric recall — context for why moving payloads out of prose into retrieval should help small models most (the E4 pass/kill asymmetry).

E5 — Caching + leaner resident scaffold keeps small models inside their context window, cutting crash/truncation

Effective Context Engineering for AI Agents — Anthropic
Argues for the smallest viable resident context and loading only what's needed just-in-time — the scaffold-trimming half of E5, directly attacking the resident-prompt size that pushes a 27b model past its window.
Small Language Models for Agentic Systems: A Survey (arXiv)
Surveys deployment trade-offs for small agentic models including context-window limits and memory pressure — situates E5's KV-cache-OOM-at-65536 ceiling as a recognized hard constraint, not a tuning preference, and reviews mitigations.
Automatic Prefix Caching — vLLM
The serving-side mechanism (KV prefix reuse) that complements a leaner scaffold: caching the static prefix reduces recompute/peak pressure on the local engine, supporting E5's "caching + less resident scaffold = stable headroom below the OOM threshold."

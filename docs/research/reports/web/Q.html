Q · LLM-authored deterministic detection rules

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

Q1 — A small model can author semgrep rules near direct-scan recall at a fraction of per-run cost

Autogrep: Automated Generation and Filtering of Semgrep Rules from Patches
Most direct prior art: LLM + multi-stage filtering turns 39,931 vuln patches into 645 reusable Semgrep rules across 20 languages — exactly Q's "author once, run free forever" model, with a concrete recall/precision pipeline.
SemOpt: LLM-Driven Code Optimization via Rule-Based Analysis
Demonstrates an agent that iteratively writes a Semgrep rule, executes it, and feeds errors back until it compiles and matches — the self-test loop Q1's mechanism describes, validating that small-model authoring with execution feedback is feasible.
DIY: Using Semgrep with LLMs to Improve Code Reviews
Practitioner walkthrough of the author-then-run split for code review — useful real-world calibration of how well LLM-authored rules generalize vs the original confirmed example.
Semgrep Multimodal: AI Reasoning + Rule-Based Analysis
Vendor confirmation that the industry direction is exactly Q's: precise rule engine for breadth, LLM reasoning only for the residual — evidence the cost model is being adopted commercially.

Q2 — Rules authored from confirmed findings accumulate into a monotonically-growing library

QLCoder: A Query Synthesizer for Static Analysis of Security Vulnerabilities
Synthesizes CodeQL queries from CVE descriptions using a Claude Code agent (100% compile, 53.4% success vs 19%/0% baselines). Shows each confirmed CVE can seed a reusable query — the "confirmed finding → generalized rule" accrual Q2 posits, just for CodeQL.
CQLLM: Generating CodeQL Vulnerability Detection Code with an LLM (RAG + LoRA)
Uses retrieval over a growing corpus of prior queries to author new ones — directly relevant to whether a rule library compounds (RAG over the library) rather than plateauing.
GitHub: CodeQL team uses AI to model APIs (more sinks, fewer FNs)
Industrial evidence that LLM-authored models accumulate into a library that monotonically expands sink coverage and lowers false-negative rate over time — the coverage-growth claim of Q2.
Automatically Generating Rules of Malicious Software Packages via LLM (RuleLLM)
Decomposes rule generation into craft/refine/align and merges redundant rules to preserve specificity — addresses Q2's "growth without precision collapse" by deduplicating as the library grows.

Q3 — Hybrid (rules for breadth + model for the novel residual) Pareto-dominates model-only on cost-per-finding

ZeroFalse: Improving Precision in Static Analysis with LLMs
Treats static-analyzer output as a structured contract and spends LLM only on adjudicating flagged residual cases — the exact division of labor Q3 needs, with measured precision/cost tradeoffs.
Information-Dense Reasoning for Efficient and Auditable Security Alert Triage
Reports a hybrid that cuts LLM calls ~40% vs pure-LLM at equivalent accuracy by letting deterministic checks clear clear-cut cases — concrete cost-per-finding Pareto evidence for Q3.
LLMs for Static Analysis: Where They Help and Where They Don't
Argues for LLMs early/broad and deterministic scanners for high-assurance verification — a clear articulation of where the hybrid frontier sits and the failure modes of each leg.
LLMs Versus Static Code Analysis Tools: A Systematic Benchmark
Quantifies where rules-only and model-only each win on recall — the baseline data needed to plot the rules-only / model-only / hybrid Pareto curve Q3 measures.

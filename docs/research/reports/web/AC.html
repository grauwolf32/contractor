AC · Deterministic observations & grounding feedback

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

AC1 — Any deterministic check contradicting the worker's self-report suppresses hallucination

Tool Receipts, Not Zero-Knowledge Proofs: Practical Hallucination Detection for AI Agents (arXiv)
Classifies every claim by epistemic source (direct tool output / inference / absence / ungrounded) and cross-references against signed tool-execution receipts the LLM cannot forge — a direct, generalized form of "reported X but never observed X" contradiction detection.
Reducing Tool Hallucination via Reliability Alignment (arXiv)
Frames tool-execution feedback as an additional signal beyond human-labeled corpora that grounds models and reduces hallucination during tool interaction — the mechanism AC bets on, that feeding back what actually happened cuts fabrication.
LLM-based Agents Suffer from Hallucinations: A Survey of Taxonomy, Methods, and Directions (arXiv)
Taxonomy of agent hallucination types and mitigation methods; useful to enumerate which contradiction checks (place-vs-read, sink-vs-trace) map to which failure modes.

AC2 — Emitted-vs-observed cross-check kills hallucinated artifacts (CRUD endpoints absent from source)

Tool Receipts, Not Zero-Knowledge Proofs (arXiv)
The "claim that no results were found" (abhāva) vs "direct tool output" distinction is exactly the emitted-endpoint-vs-observed-file check: any emitted item whose evidentiary basis is absent from a real tool receipt is flaggable.
Reducing hallucinations with custom intervention using Amazon Bedrock Agents (AWS)
Production pattern of intercepting agent output and validating each asserted item against a ground-truth source before emitting — the same gate as flagging an endpoint never present in a read file.

AC3 — Observations raise recall WITHOUT injecting run-to-run variance (deterministic)

How Consistent Are LLM Agents? Measuring Behavioral Reproducibility in Multi-Step Tool-Calling Pipelines (arXiv)
Quantifies that variance compounds across multi-step agent trajectories; deterministic tools isolate model variance from environmental noise — supporting the claim that a computed (not generated) observation block adds zero variance.
Dissecting Non-Determinism in Large Language Models (ICLR Blogposts 2026)
Documents ~5.5% run-to-run and 9% prompt-variant variance even at temp 0 — establishes that the ±0.07 F1 in the study is intrinsic model noise, not noise the observation channel can be blamed for.
Replayable Financial Agents: A Determinism-Faithfulness Assurance Harness (arXiv)
Argues for deterministic, replayable feedback channels in tool-using agents so behavior is auditable and reproducible — directly the safety-of-the-lever argument behind a byte-identical observation block.

AC4 — Small-LLM lever: recall lift replicated on 27b/35b, may be larger for smaller models

Externalization in LLM Agents: A Unified Review of Memory, Skills, Protocols and Harness Engineering (arXiv)
"Externalization converts an internal recall problem into an external recognition-and-retrieval problem" — precisely why observations substitute for the working memory a small model lacks; predicts the lift grows as parametric capacity shrinks.
Memory in Large Language Models: Mechanisms, Evaluation and Evolution (arXiv)
Survey of memory mechanisms; supports that surfacing curated history ("you already looked here, found this") boosts coherence/recall, with smaller models benefiting more from external memory augmentation.

AC5 — More observation dimensions pay off (coverage gaps, graph-reachability, malformed/retry)

Reducing Tool Hallucination via Reliability Alignment (arXiv)
Shows accurate/elaborate execution feedback validates and enhances outputs — supports adding coverage and reachability dimensions, while cautioning (per the study's errors-arm result) that not all signal is net-positive.
Mitigating LLM Hallucinations Using a Multi-Agent Framework (MDPI Information)
Uses a scoring function over response factuality in a controlled feedback loop; a model for adding each new deterministic dimension as a scored arm and dropping neutral ones.

AC6 — Observations are a tunable precision/recall dial; route per use-case

What is grounding and hallucinations in AI? (K2view)
Explains grounding strength as a tunable trade-off between coverage (recall) and faithfulness (precision) — conceptual backing for exposing lean (recall) vs lean+paths (precision) as a documented dial.
Best Practices for Mitigating Hallucinations in LLMs (Microsoft)
Recommends matching grounding/verification intensity to use-case risk tolerance — the scanner-vs-PR-gate routing AC6 proposes.

AC7 — Tool arguments (not just counts/paths) as observations; risk of the errors-arm failure

Tool Receipts, Not Zero-Knowledge Proofs (arXiv)
Receipts include the actual tool inputs/outputs, enabling premise-checking of inferences ("claimed SQLi but no arg matched a query sink") — exactly the gap/contradiction detection projecting grep patterns and HTTP payloads would unlock.
Best Practices for Controlling LLM Hallucinations at the Application Level (Parasoft)
Warns that more context/feedback is not monotonically better — over-feeding raises noise and token cost — corroborating the honest "errors-arm failure mode" risk for tool-args.

AC8 — Task-relevance scoping of observations beats projecting everything

Distilling Feedback into Memory-as-a-Tool (arXiv)
Distills/filters feedback into a curated, relevance-scoped memory rather than dumping all signal — the principle behind projecting only the task-relevant slice of tool args to control the noise/token blowup.
Externalization in LLM Agents (arXiv)
Frames the harness's job as surfacing a "curated slice of history" the model can recognize — task-scoped projection is the curation policy; all-args is the un-curated baseline this argues against.

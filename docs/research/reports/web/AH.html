AH · Cascade decay & the verification funnel

Web-sourced prior art for the unifying theory behind the pipeline. Links are real web-search results; relevance notes are the researcher's synthesis.

AH1 · Observed recall stays above naive p^N because filters have retention ρ≈1, not p≈0.8

Instrument per-stage accuracy on labeled fixtures; plot observed end-to-end vs. predicted p^N. The gap is the filter stages, whose retention ρ is near 1 (they reject, they don't re-derive).

Solving a Million-Step LLM Task with Zero Errors (MAKER) — arXiv:2511.09030
The canonical statement of the doom curve: a monolithic process with per-step accuracy p is guaranteed to fail at scale (a 99%-step process fails by ~few hundred steps). MAKER beats it by extreme decomposition + per-step error correction — i.e. raising effective ρ per step, not the model. Direct theoretical anchor for "why naive p^N predicts collapse and what breaks it."
The Reliability Compounding Problem in AI Agent Stacks — MindStudio
States the multiplicative model cleanly: P(success) = (1−p)^m over m sequential steps; 95%/step → 36% at 20 steps. This is exactly the p^N baseline against which our instrumented per-stage curve is plotted.
The Six Sigma Agent: Enterprise-Grade Reliability through Consensus-Driven Decomposed Execution — arXiv:2601.22290
Proves error can be driven down exponentially (O(p^⌈n/2⌉) via consensus over n samples) rather than up — concrete evidence that a stage's effective retention need not be the raw model p. Supports modeling filter stages with ρ≈1.
From Spark to Fire: Modeling and Mitigating Error Cascades in LLM-Based Multi-Agent Collaboration — arXiv:2603.04474
Formalizes cascade amplification / consensus inertia in multi-agent chains and shows a governance layer that stops "final infection" in ≥89% of runs — i.e. the decay is not inevitable once you separate propagation from re-generation. Frames why measuring the gap matters.

AH2 · The funnel: recall flat/falling, precision rising — filters add precision without a generator's recall hit

Across stages the contract is asymmetric: a pure filter can only reject, so recall is monotone non-increasing while precision climbs — the signature of generate→filter→filter, not generate→generate.

Cascading classifiers — Wikipedia
The classical analog of the funnel: each stage rejects negatives and forwards candidates; total sensitivity (recall) is the product of stage sensitivities while precision rises stage-by-stage. Designers deliberately keep early-stage recall ≈100% (ρ≈1) — exactly the funnel discipline "wide net first, then verify."
Variation in Verification: Understanding Verification Dynamics in Large Language Models — arXiv:2509.17995
Documents verification asymmetry: models catch errors in existing content more reliably than they avoid them while generating. This is the mechanism by which a verifier stage can raise precision without behaving like a (recall-multiplying) generator.
LLM Verification Loops: Best Practices and Patterns
Summarizes the convergence result that rounds 1–2 of verification capture ~75% of reachable improvement, arguing for "wide" (multiple filters) over "deep" (endless iteration) — matching the trace + exploit-verify two-filter funnel shape.

AH3 · Control arm: a generator-only chain (N scans unioned) has precision COLLAPSE; the funnel's precision climbs

Unioning N independent generative passes maximizes recall but accumulates each pass's false positives — precision falls as passes grow. Contrast with the filter funnel where precision rises.

MultiVer: Zero-Shot Multi-Agent Vulnerability Detection — arXiv:2602.17875
The control arm made literal: four generator agents combined by union voting gain +17pp recall but precision drops to 48.8% vs 63.9% single-detector. Direct evidence that generator-only unions trade precision away — the opposite of the verification funnel.
Sampling-aware Adversarial Attacks Against Large Language Models — arXiv:2507.04446
Quantifies how repeated sampling exploits a judge and inflates false positives (precision ~59%→54% on borderline cases) — the union-of-passes failure mode. Supports the prediction that more generative passes erode precision.
From Spark to Fire: Modeling and Mitigating Error Cascades — arXiv:2603.04474
Shows multi-generator collaboration amplifies a single injected error into system-wide false consensus — the precision-collapse mechanism for generator-only chains, and why the union control arm should degrade rather than improve.

AH4 · Context Rot lowers each stage's accuracy p as input grows; per-stage context minimization raises p and end-to-end recall

Each stage's p is a function of its input length. Smaller models hit the wall sooner; shrinking each stage's context (artifact-only handoffs, focused subtasks) raises p, and a higher p per stage lifts the whole funnel.

Context Rot: How Increasing Input Tokens Impacts LLM Performance — Chroma Research
The 18-model study: every model degrades as input grows, even at perfect retrieval; models do not use context uniformly. This is the direct empirical basis for treating per-stage p as length-dependent — and the motivation for per-stage context minimization.
Context Length Alone Hurts LLM Performance Despite Perfect Retrieval — arXiv:2510.05381
Isolates the variable: length itself degrades performance even when all relevant tokens are perfectly retrievable (and even when distractors are masked to whitespace). Their fix — recite the evidence to convert a long-context task into a short one — is exactly per-stage context minimization. Strongest causal source for AH4.
Optimizing Prompts (task decomposition + focused context) — Prompt Engineering Guide
Practitioner synthesis: decomposing into focused subtasks and minimizing per-prompt context improves reliability vs. one comprehensive prompt — the operational lever for raising stage-level p in the funnel.

AH5 · capability = harness × model; below frontier scale the harness term dominates, and lifts small models MORE

If harness and model are substitutes (not complements), the harness lift is larger where the model is weaker — so a well-built harness closes more of the small↔frontier gap than it adds at the top.

awesome-harness-engineering (curated list) — GitHub
The "Agent = Model + Harness" framing as a discipline: tools, schemas, context management, guardrails. Establishes the harness × model decomposition AH5 is built on.
Why Scaffolding Matters More Than the Model — MindStudio
Cites concrete harness deltas larger than model swaps: Vercel 80%→100% by cutting tools (same model); Princeton CORE-Bench 42%→78% same model, different scaffold; Cursor 46%→80% on harness alone. Direct evidence the harness term dominates below frontier.
Harness engineering for coding agent users — martinfowler.com
Argues agentic scaffolding acts as a "competence floor" — the negative tail of weak models disappears under a good harness while strong models gain less. This is precisely the substitutes-not-complements claim: bigger lift for the weaker model.
SEC-bench: Automated Benchmarking of LLM Agents on Real-World Software Security Tasks — arXiv:2506.11791
Provides the apples-to-apples security harness on which a same-benchmark, swap-the-model ablation (the AH5 killer chart) could be run; baselines top agents at ≤18% PoC / 34% patch, leaving wide headroom for harness lift to be measured.

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

R1 — An inferred "handler → expected guards" model flags missing-authz outliers better than the checklist

Automatic Detection of Access Control Vulnerabilities via API Specification Processing
Builds a model of API endpoints and derives the set of expected-but-absent authorization checks — the "handler → expected guards" population R1 wants to infer, evaluated as IDOR/BOLA detection.
Automated BOLA Detection in REST APIs via OpenAPI → Colored Petri Nets
Transforms the OpenAPI surface into a behavioral model to detect object-level-auth gaps automatically — concrete precedent for modeling guards across the handler population rather than checklist matching.
LLMs Are Finding Critical Business-Logic Vulns (IDOR) — and They're Everywhere
Argues LLMs detect missing-authz by inferring intended access rules from code rather than pattern lists — the LLM realization of R1's outlier-detection idea, with field results on real codebases.
OWASP API Top-10: Broken Object-Level Authorization (BOLA)
Authoritative definition of the target vulnerability class (BOLA/BFLA) and why it is fundamentally an absence-of-control problem — frames why population-level inference beats a sink checklist for R1.

R2 — Population-anomaly framing reduces false positives vs pattern matching

Engler et al., Bugs as Deviant Behavior: Inferring Errors in Systems Code (SOSP'01)
The seminal "statistical deviance" paper: infer beliefs the population holds, flag only contradictions, and rank by frequency — exactly R2's "a handler matching its siblings isn't flagged" precision mechanism, with low-FP results on Linux/OpenBSD.
The Daikon System for Dynamic Detection of Likely Invariants
Canonical likely-invariant miner; its support/confidence filtering is the standard way to suppress spurious invariants — the calibration knob R2 needs so the anomaly model stays high-precision.
Reducing False Positives in Static Bug Detection with LLMs (industry study)
Quantifies how much of static-analysis FP noise comes from ignoring code semantics, and how LLM context reduces it — direct evidence for R2's precision-vs-pattern-matching claim and the "FP-trap survival" metric.
LLM-based Vulnerability Detection at Project Scale: An Empirical Study
Project-scale evaluation showing LLMs flag fewer benign sinks when they reason about whether a handler conforms to its peers — empirical backing (and FP caveats) for population-aware flagging.

R3 — Inferred invariants catch violations the checklist never enumerated (novel business-logic flaws)

Anota: Identifying Business Logic Vulnerabilities via Inferred Specifications
Closest prior art for R3: infers behavioral specs/intent and flags deviations to catch business-logic flaws outside any fixed taxonomy — the non-taxonomic recall R3 targets.
LogicScan: LLM-driven Detection of Business Logic Vulnerabilities in Smart Contracts
Uses inferred intended behavior (not pattern lists) to find logic bugs in contracts — demonstrates the generalization-beyond-checklist mechanism R3 hypothesizes in a different domain.
Business Logic Vulnerabilities: A Detection Framework Using AI
Survey/framework on AI for logic flaws, with a Business Specification Language to extract structured intent from code while curbing hallucination — relevant to making R3's inferred invariants reliable.
Daikon: likely invariants as implicit behavioral specifications
Shows invariants serve as machine-checkable specs against which violations are detected — the classical basis for "inferred invariant ⇒ flag any code that breaks it," including bugs nobody enumerated.

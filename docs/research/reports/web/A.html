A · Token efficiency & cost

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

A1 — Prompt caching of the static prefix cuts input tokens ≥40% with no quality change

Prompt caching for faster model inference — Amazon Bedrock docs
Vendor reference for the exact mechanism A1 proposes: marking the static prefix (system prompt + schema trailer) as a cache checkpoint so re-sends bill at the cached rate. Documents the breakpoint/checkpoint API directly applicable to plumbing cache_control.
How We Cut LLM Costs by 59% With Prompt Caching — ProjectDiscovery
A security-tooling vendor reports a measured 59→70% cost cut from caching the static system prefix of an agentic pipeline — the closest real-world analogue to Contractor's case (repeated ~15KB worker prompt over many turns), and a concrete data point for the ≥40% claim.
Prompt Caching: 60% Cost Reduction in LLM Applications — Thomson Reuters Labs
Engineering writeup with breakpoint placement guidance: cache reads at 0.1× input price, 25% write premium, last-static-message as first breakpoint. Useful for sizing expected savings and the cache-write amortization break-even.

A2 — Byte-bounded heavy-result retention reduces peak prompt size ≥30% without lowering recall

ACON: Optimizing Context Compression for Long-horizon LLM Agents (arXiv)
Unified history+observation compression framework reporting 26–54% peak-token reduction while holding task success — directly supports the A2 thesis that bounding heavy tool-result retention cuts peak input without recall loss.
Context Window Management for AI Agents: Summarization, Pruning, Sliding Window
Survey of retention strategies; notably documents "observation masking" (replace old tool outputs with a placeholder while keeping the call) halving cost at parity on SWE-bench — a stronger variant of byte-bounded eviction worth evaluating against the count-only keep-last-15 today.
SWE-Pruner: Self-Adaptive Context Pruning for Coding Agents (arXiv)
Trains a 0.6B skimmer for task-aware pruning, achieving 23–54% token reduction on coding agents — evidence that selectively dropping large tool reads preserves recall, and a more sophisticated alternative if a static byte budget proves too blunt.

A3 — Pruning (drop oldest tool results) beats appending a summarization nudge on over-budget runs

Context Engineering for Agents — LangChain
Canonical taxonomy (write/select/compress/isolate) arguing compaction should remove signal-poor content rather than append; frames why a growing "wrap-up" nudge is an anti-pattern versus eviction.
Context Compaction for AI Agents: A Complete Guide — Redis
Recommends a multi-layer cascade — compress tool outputs first, sliding-window trim second, LLM summarization only as last resort — exactly the ordering A3 proposes (prune before nudge), and notes summarization stalls inference for tens of seconds.
Scaling Long-Horizon LLM Agents via Context-Folding (arXiv)
Shows folding/pruning agents match or beat ReAct with a 10× smaller active context and outperform summarization-based management — direct evidence that dropping stale results lowers tokens without hurting completion on long-horizon (75-step scan) tasks.

A4 — A cross-subtask file-read cache cuts redundant read_file tokens materially

ToolCache Agent: Accelerating LLM Agents Through Intelligent Tool Call Caching
Caches tool-call results by argument identity with per-tool cacheability/expiry/invalidation rules — exactly the "already read, see prior result" handle A4 wants for unchanged files, with stated correctness handling for stateful tools.
Asteria: Semantic-Aware Cross-Region Caching for Agentic LLM Tool Access (arXiv)
Observes file accesses follow a near-Zipfian distribution so caching hot files removes many redundant fetches — empirical backing for A4's premise that a small set of files dominates duplicate reads across subtasks.
TVCache: A Stateful Tool-Value Cache for Post-Training LLM Agents (arXiv)
Reports cache hit rates up to 70% and large reductions in tool execution time across terminal/SQL/video workloads — quantifies the upside ceiling for deduping repeated tool calls in an agent loop.

A5 — Repair-only re-prompting beats n_retries=3 full re-run on malformed worker output

json_repair — repair malformed JSON from LLMs (GitHub)
Deterministic local repair of malformed LLM JSON with no extra model call — the cheapest form of A5's "fix, don't re-run", suitable as a pre-parse pass before any re-prompt is attempted.
Advanced Output Parsing Strategies (LangChain RetryParser / OutputFixingParser)
Documents the retry-with-error-feedback pattern: re-prompt with the original prompt + faulty output + parse error to correct only the structure — the A5 mechanism, and notes it adds far less than a full re-run since the reasoning already happened.
LangChain issue: slow retries on JSON parse error in structured output
Real-world report that naive full-regeneration retries on structured-output parse failures are "extremely slow" — concrete evidence of the waste A5 targets and why feeding back just the error is preferable.

A6 — elide tool results to id-handles (recall by lookup)

MemGPT: Towards LLMs as Operating Systems
Virtual context management: out-of-context data lives in "external context" and is paged back into the window on demand via function calls — exactly the recall-by-handle pattern A6 wants (keep a reference, dereference only when needed).
Context editing (clear_tool_uses) — Claude API docs
The shipped precedent for dropping stale tool results once over a token threshold, leaving a placeholder. A6's twist: make that placeholder a real handle (request_id) the agent can look up, not an opaque stub.
Managing context on the Claude Developer Platform
Reports 84% token reduction in a 100-turn tool-use eval from clearing stale tool results — quantifies the upside of A6 for a long HTTP-probing exploit loop.
Virtual context management with MemGPT and Letta
Practical walkthrough of paging between in-context and external memory by reference — a working model for an "elide-to-handle + lookup tool" callback variant.

Z · Knowledge architecture — the engagement artifact pool

Web-sourced prior art, tools, papers and articles relevant to this direction. Links are real web-search results; relevance notes are the researcher's synthesis.

Z1 — Deterministic pool retrieval ~0 run-to-run variance; embedding-RAG does not

On The Reproducibility Limitations of RAG Systems
Quantifies run-to-run instability across the RAG pipeline (embedding model, precision, data insertion) using Exact-Match / Jaccard / Kendall's Tau — exactly the variance the deterministic pool avoids by construction.
ReproRAG: Benchmarking RAG Reproducibility
A framework measuring the same Jaccard-of-retrieved-set metric Z1 proposes, isolating each variance source — a ready-made instrument for the pool-vs-RAG stability test.

Z2 — Deterministic retrieval shrinks eval-metric variance, making smaller effects detectable

Quantifying Variance in Evaluation Benchmarks
Decomposes benchmark variance and shows how it sets the floor on the minimum detectable effect — formalizes Z2's claim that cutting retrieval noise tightens the CI on F1.
Measuring All the Noises of LLM Evals
Separates prediction noise from data noise and ties statistical power to noise level — the rationale that removing a noise source (RAG) raises detectable-effect resolution.
A/B Testing LLM Prompts in 2026: Best Practices and Pitfalls
Matched-pair design cancels between-example variance, tightening CIs by 1–2 orders of magnitude; deterministic context is the same move applied to retrieval — directly supports "RAG makes hypotheses hard to test."

Z3 — A typed "leads / suspicious" backlog distinct from confirmed findings raises recall when deepened

Hound: Relation-First Knowledge Graphs for Complex-System Reasoning in Security Audits
Maintains undecided hypotheses with intermediate confidence/status ("investigating"/"supported") and turns them into confirmations via graph + evidence slices — a direct model for a typed leads backlog feeding deepening.
False-Positive Triage in SAST + DAST
Argues single-signal findings shouldn't be trusted but should be cross-verified rather than dropped — supports storing low-confidence leads separately and escalating them instead of conflating with findings.
How to Triage Security Findings — Five Steps
Practitioner workflow that explicitly preserves open leads and escalates static findings once backed by runtime evidence — the precision/recall tradeoff Z3 wants to measure.

Z4 — Content-addressed artifacts skip re-deriving what's known, cutting tokens

Artifact-Based Build Systems (Bazel)
Canonical content-addressed model: a task reuses a cached artifact only if its input hash matches — the deterministic cache-hit mechanism Z4 borrows for analysis artifacts.
The Go Build System: content-addressed cache
Stores every compiled package and tool output keyed by content hash to reuse work across invocations — concrete reference for hash-keyed artifact reuse with deterministic hits.
Remote Cache CDC: Reusing Bytes (BuildBuddy)
Content-defined chunking reuses unchanged chunks of large outputs rather than recomputing/re-uploading — applicable to caching large analysis artifacts at sub-file granularity.

Z5 — A typed engagement graph (finding→endpoint→trace→evidence) lets agents traverse rather than re-derive

Hound: Relation-First Knowledge Graphs for Security Audits
Builds a relation-first KG where every claim links to evidence slices, so the auditor traverses to the exact evidence instead of re-reading source — the engagement graph Z5 describes, in a security-audit setting.
Graph Memory for LLM Agents: the relational blind spots flat vectors miss
Argues flat vector recall can't recover how facts relate, breaking multi-hop reasoning — the case for typed relations + provenance over last-write-wins flat storage.
AriGraph: Knowledge-Graph World Models with Episodic Memory for LLM Agents
Agent memory as a typed graph traversed for multi-hop reasoning, outperforming flat retrieval — evidence that traversal beats re-derivation for downstream agents.
Graph Database AI Agents: GraphRAG & Memory Guide
Reports GraphRAG precision gains up to ~35% over vector-only and full provenance chains through nodes/edges — supports the accuracy-and-no-overwrite-loss claim of a typed engagement graph.

Z6 — Falsify the skepticism: pinned RAG reaches pool-level reproducibility, or it doesn't

On The Reproducibility Limitations of RAG Systems (ReproRAG findings)
Empirically falsifies the assumption that ANN algorithms are the main randomness source: core indexing/search is run-to-run stable under proper control; data insertion and precision drive the drift — exactly Z6's "intrinsic vs unpinned" question, with a partial answer that pinning helps a lot.
Literature review: Reproducibility Limitations of RAG Systems
Synthesis confirming determinism flags + data versioning + precision management can make retrieval perfectly stable — a checklist for the "pinned RAG" arm of the Z6 experiment.

The one clear win: QW3

Byte-bounded retention cut input tokens ~44% and peak prompt ~42% on a real vuln-scan, with every key true-positive retained (the on-arm even found a few more). The peak dropping to ~29.6k — right at the 30k char budget — is deterministic confirmation the mechanic bound. Default fs_heavy_keep_budget_chars=0 keeps it a no-op, so it's safe to merge and enable per-workflow. (n=1; the call-count drop is partly variance, but the peak-capping is mechanical, not stochastic.)

The meta-findings (more valuable than any single win)

  • Structural FP filters don't bind, because the 27b's FPs aren't structural. QW1 (hallucinated file locations) and QW7 (lexical duplicates) both found nothing to act on — the model's false positives are plausible-but-wrong findings in real, read files. Precision here needs a semantic verifier (the cascade/funnel — Direction AH, or an LLM-judge), not structural post-filters. Both filters are correct and safe, just inert on this failure mode.
  • Telling a small model to "report less" backfires. QW6's precision prompt collapsed the 27b to 0 findings. Small models over-comply with suppression instructions → recall crater. Precision must be earned by verification stages, not by stricter generation prompts. (Validates the verification≠generation thesis, AH.)
  • pass@1 on small fixtures is noise-dominated. Only large effects cleared the bar: QW3's −44% tokens (real) and QW6's total collapse (real). The interesting quality deltas — QW5's +0.067 F1, QW1's FP 2→3 — are inside the ±0.07 / ±1-FP run-to-run noise the project already documented. Decisive quality A/Bs require pass@N (N≥5). This is Direction F, observed first-hand.
  • Recall prompt (shannon) helps but isn't free. +0.067 F1 came with +66% input tokens and 2× wall — a real cost/quality tradeoff to weigh, pending a pass@N confirmation.

Round 2 — generalization on a second project (realvuln-dvblab)

  • QW3 does NOT cleanly generalize. dvblab off=52 calls/1.13M/peak 36,412/13 finds; on(budget 15k)=74 calls/1.55M/peak 52,291/22 finds — the on-arm went higher on everything because it ran longer. dvblab's heavy reads are tiny (~23 KB code) so the budget barely binds, and run-length variance (52 vs 74 calls ≈ ±40% tokens) swamped the effect. QW3 is a conditional win — it binds only when heavy-tool reads are large (vampi had big file reads → clean −42% peak); on small-codebase scans it's a no-op. Mechanism sound + safe, benefit fixture-dependent.
  • QW7 generalizes as a safe no-op (dvblab offline: 13→13, merged 0) — distinct findings, no lexical dups, on both projects.
  • QW1 structurally no-op on dvblab too (all findings in real, read /backend/* files) — same pattern as vampi.
  • QW8 inconclusive on tractable fixtures. dvblab's 6-file scan covered ~all files → coverage-gap ≈ empty → no-op. It needs a large project to matter — and the large one (dvpwa, 25 files) stalled the model at 532 calls from unbounded-context overflow (GPU idle, model healthy) — itself evidence for context economy, but unusable as a baseline.
The Round-2 lesson (load-bearing): n=1 CLI runs carry ±40% token / ±finding variance from run-length alone. At this fidelity only deterministic mechanics (QW4 plumbing; QW3's per-prompt peak-cap) and large effects (QW6's collapse) are measurable — everything else is noise. Robust token/quality numbers require controlled pass@N with a fixed step budget, which is a multi-hour GPU campaign. Blind pass@N on non-binding small fixtures would mostly measure variance.

FP audit — the eval under-measures precision & recall

Manually verified the QW3 dvblab on-arm "8 FP" against source. With lenient file+CWE matching only 2 findings are truly unmatched; the eval's FP=8 is inflated by one-to-one + line±10 matching (dvblab has 9 GT cases in auth_routes.py alone, so multiple real bugs in one file can't each claim a GT slot). Of the 2 truly unmatched:
  • REAL vuln missing from GT: requirements.txt PyYAML 5.3.1 → CVE-2020-14343, and reachable (auth_routes.py:157 calls yaml.load(..., Loader=yaml.Loader) on user input). The model found an SCA-class bug the eval doesn't even test for (Direction J). Scored FP, actually a true positive.
  • Genuine weak FP: frontend client-side JWT decode of the user's own token — benign pattern, and out of the backend-only GT scope.
dvpwa on-arm FP audit (controlled run): 2 "FP" → 1 genuine FP (app.py CWE-798 hardcoded-creds — no credentials in app.py; real file, wrong issue) + 1 real vuln missing from GT (templates/evaluate.jinja2 renders {{ student.name }}/{{ course.name }} unescaped under global autoescape=False — genuine stored XSS, GT only listed other templates). So dvpwa true precision ≈ 5/6 = 0.83, not the reported 0.67.

Conclusion: across both audited projects ~half the "FPs" are real findings the eval can't credit (dvblab PyYAML SCA; dvpwa evaluate.jinja2 XSS), the rest genuine/weak. The model's true precision is well above the reported numbers; QW3's on-arm "extra FPs" are mostly real findings the eval can't credit, not hallucinations. This reinforces the meta-finding: strict-match scoring + incomplete GT systematically under-counts the model, and a semantic verifier (not strict structural scoring) is the right precision lever.
Note (per request): recall on vulns is the priority metric. This is a security scanner — missing a real bug is worse than emitting an extra finding a human triages away. So: (1) tune/accept changes to protect recall first (a change that holds recall and cuts tokens/precision-noise is good; one that trims recall is suspect even if F1 rises); (2) treat reported FP counts skeptically — audit them (as above) before believing a precision regression, since GT is incomplete and matching is strict; (3) prefer recall-preserving levers (context economy, verification-for-precision) over generation-suppression (QW6 killed recall).

Recommendation

Merge now (low-risk, gated/no-op by default, unit-verified):
  • QW3 byte-retention — and enable with a sensible fs_heavy_keep_budget_chars on the token-heavy scan workflows.
  • QW4 eval cost metric — pure instrument, unblocks measuring every future token A/B.
  • QW1, QW7 — keep as gated tools (off by default); they're safe and will earn their keep on hallucination-/duplicate-prone targets (large multi-file repos, ensemble outputs), just not on vampi.
  • QW8 — merge the gated mechanism; it needs the capture_in_scope wire-up before it can be eval'd.
Do not promote / rework:
  • QW6 v4 — over-suppresses the small model; rewrite gentler (or drop). Leave active: v3.
  • QW5 shannon — run a pass@5 A/B before deciding; weigh +F1 against +66% tokens.
Follow-up experiments (the data points to these):
  • Build the semantic precision lever the structural filters can't be: a verification/LLM-judge pass over scan findings (Direction AH/L) — the FPs we saw are exactly what it targets.
  • Adopt pass@5 + the QW4 cost metric as the standard A/B unit so quality deltas clear the noise.
  • Re-test QW1 on a known hallucination-prone target; QW7 with a semantic (embedding/LLM) dedup, not lexical.

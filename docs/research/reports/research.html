How the 51 directions fit together

Read this first. The directions aren't a flat list — they're corollaries of two meta-principles, organized around one theory and a single pipeline lifecycle.

Two meta-principles (most directions descend from one or both):

  1. Organize knowledge as typed, deterministically-retrievable, composable units in LLM-legible formats. → X formats · Z artifact pool · AA skill taxonomy · AE prompt layers · M diff artifacts · AJ pinned RAG · O experience memory.
  2. Every stage emits scorable, falsifiable, deterministically-grounded units. → AB hypotheses · AC observations (✓ the one validated direction) · M verifiable artifacts · C/AH verify funnel · F measurement · AK refine-from-results.

The theory (AH) — why the rest works. A chain of generators decays as p^N and context rot lowers each p; but verification ≠ generation — a filter can't manufacture a false positive, so recall can only fall, precision can rise. Hence the whole design: maximize recall cheaply with a wide net, then refine precision with targeted verifiers. AH is the principle beneath C, K, L, W and AD.

The pipeline spine — directions map onto a lifecycle:

AB generate → Z store → AD compose → W run · AL iterate → Y/U schedule → AC ground → C/AH verify → M/X emit → AK refine

…with AA / X / G / H / I supplying knowledge & code-navigation, F / Z2 / K / L / V keeping it measurable, E the cross-cutting small-LLM mission, AI / AJ optional opt-in levers (frontier escalation, RAG), and D the simplification pressure on all of it. Two orthogonal search axes recur: Y searches the codebase (breadth-scan vs depth-trace); AL searches the plan space (depth within a run × breadth across iterations).

Tiers. A–M sharpen today's pipeline · N–W are net-new frontier bets (each gated behind one decisive experiment) · X–AA + Z are foundational/knowledge lenses · AB–AL extend hypothesis-gen, grounding, composition, prompt layers, loop-control, output, theory, escalation, RAG, auto-refinement, the iteration search and stop-condition sizing · AH is the unifying theory · AC is the only direction already experimentally validated (off→lean: +4–5.5 true vulns at flat cost across 3 models) — proof the test-driven method delivers.

Where to start (cheapest, most decisive): F4+F2 fix measurement → A1 prompt caching → extend the validated AC (the AC2 emitted-vs-read cross-check) → W1 attribute planner tokens → AH1 plot observed-recall vs p^N → B1 activate the shannon prompt. Each direction's title and every hypothesis id links (↗ new tab) to a web/ file of web-sourced prior art.

Executive summary

Four agents mapped the pipeline independently. The convergent picture:

  • The capability floor is already strong. Tree-sitter structural search across 19 languages, a real call graph (callers/callees/reachability/attack-surface), an HTTP+Caido probing stack, a Kali code-exec sandbox, and a deep skill library (trace, vuln_scan, exploit, vulns, auth, stride). The "AST search / code navigation" gap from prior research is closed.
  • But the run is expensive and leaky. cached_tokens = 0 everywhere — no prompt caching — so a 15–17 KB worker prompt is re-billed on every one of 20–75 model turns. XBOW captures cost ~905k input tokens each. Retries re-run whole plans; summarization adds a nudge instead of pruning.
  • Detection is single-pass and partly overfit. The graph/direct trace variants run the worker exactly once per operation with no iteration; the active codereview v3 prompt hardcodes grep/WordPress patterns (overfit risk); stronger shannon prompts exist but are inactive.
  • Exploitation is only truly verified for XBOW. Detection/verdict evals accept self-asserted evidence; exploitable_unverified counts as a pass. Real end-to-end proof exists only via the XBOW flag and the Caido proof-chain.
  • The surface has grown faster than it has been consolidated. Four near-identical trace workflows, a fragile hardcoded namespace coupling, unwired agents, and three artifacts per task — all maintenance drag with no capability return.

Token efficiency & cost

Impact: HighEffort: Low–MedMission-critical
Thesis

The pipeline pays full price for a context it never caches and prunes only weakly. At ~905k input tokens per XBOW capture, cost — not capability — is the adoption blocker for self-hosters. The largest single lever is prompt caching of the static prefix.

Grounding
  • cached_tokens is recorded in metrics.jsonl and reads 0 — no cache_control plumbing anywhere.
  • Worker prompt is 15–17 KB, re-sent every model turn; scan tasks run max_steps 50–75.
  • SummarizationLimitCallback (context.py:16) appends a nudge on every over-budget call instead of pruning.
  • FunctionResultsRemovalCallback keeps last 15 heavy results with keep_budget_chars=0 (count-only); skills_read/read_memory are never elided.
  • max_attempts > iterations (e.g. oas_enrich 6/3) re-runs the whole plan; worker n_retries=3 re-runs all tools on a single malformed parse.

Thesis

Impact: Med–HighEffort: Medplanner mechanism · author-flagged

Test-scenario refinements to existing directions

Impact: High (protocol)Effort: LowAddendum · edits, not new work
Thesis

Seven sharpenings to already-specified tests. #1 and #2 are edits to the shared verification protocol — apply once and everything downstream tightens.

#1 — Correct the mission-asymmetry ceiling bias (affects E1–E5, G3, H2, L3, O3, X4, AA1, AC4, AE2, AH5, AI, V — the entire small-LLM axis). uplift(27b) > uplift(70b) is confounded: a 70b at 0.90 baseline has ≤0.10 headroom vs the 27b's 0.50, so larger 27b uplift is partly mechanical, not mechanism. Fixes: (a) report headroom-normalized uplift Δ/(1−baseline) or gap-closure fraction, not raw Δ; (b) void the asymmetry test when the 70b baseline is ceilinged (>~0.85 on the fixture) — pick harder fixtures where the large model isn't saturated, or the comparison is uninformative; (c) prefer the gap metric recall70−recall27 (E1/G3/H2 already use it) but guard it against ceiling-driven shrinkage. One edit applied to ~15 hypotheses — the difference between measuring the mission and measuring headroom. Compounds with AS3 (part of the gap may be contamination, not capability).
#TargetRefinement
2all A/BsCommon-random-numbers / paired seeds. The memo pairs on fixture but not on the sampling seed across arms. Pinning it (CRN) so arm-A and arm-B see identical decode randomness turns each A/B into a paired-difference test — often 2–5× variance reduction, letting the same pass@N detect smaller real effects. Directly attacks the "quick-wins were noise" problem. Needs a --seed path in serve.sh + eval (absent today), and AR1 first to know how much determinism the stack can deliver.
3the A/B harnessSequential early-stop for the experiments themselves. Running every arm to a fixed pass@N over-spends on clearly-null and clearly-huge effects. A sequential test (SPRT / group-sequential) stops each A/B as soon as the effect clears or fails its band — the eval's own token bill drops with no loss of rigor. Meta-applies U3/AM3 to the experiment loop.
4N2Reverted real patches over synthetic injection. "Inject vulns into diffs" produces synthetic bugs that may not resemble real introduced ones. Prefer reversing real security-fix commits (SStuBs / CVEfixes / the N-day corpus): the reverted patch is the ground-truth introduced bug, at zero labeling cost and full realism. Keep synthetic (P) for volume; use reverted patches for the validity anchor.
5Q1Close two open holes. (a) Circular without a seen/held-out split — rules authored against known examples encode fixture specifics (the overfit B4/F3 police); author on a golden split, score on held-out. (b) Uninformative without the AO floor — the bar isn't "authored rule vs the model," it's "authored rule vs semgrep's default ruleset"; if authoring doesn't beat the free default it added nothing. Fold AO1 in as Q1's baseline.
6B5Score above-floor and report the interaction. {27b,70b}×{semgrep on/off} conflates "semgrep closes the gap" with "semgrep helps both." Report the interaction term (does semgrep uplift 27b more than 70b?), not just the 27b+semgrep ≥ 70b cell; and credit only above-floor recall (AO) so a "win" isn't semgrep's own deterministic finds re-counted as model capability.
7AC3 / Z1 / Z2Separate serving noise from "model noise." These conclude a byte-identical injected block ⇒ residual variance is intrinsic model noise. But AR1 shows a serving variance term (batching nondeterminism) that is neither retrieval (Z) nor GT (AP) noise. Re-state the pass criterion as "observation-block byte-stable and outcome σ ≤ AR1's serving floor," else some of the ±0.07 attributed to model noise is removable serving noise.
Where these plug into the priority matrix
  • Do-first (measurement, ~free, protects everything): AR1 serving floor, AR2 scorer sweep, AT1 miss-decomposition backfill, AU1 wall-clock conversion — all backfill over stored runs except AR1's repeat sweep. Same tier as F4/F2/AN1/AO1/AP1.
  • Decisive experiments (run before trusting the recall numbers): AS1 perturbation-sensitivity, AS2 public-vs-fresh — if contamination is large, much of the memo's recall re-baselines.
  • Protocol edits (apply once, everything downstream tightens): refinement #1 (ceiling correction) and #2 (CRN seeds).

# UI design review follow-up — September 22, 2026

Scope: the demo stand at UI 0.5.3 after the V58 series and the 2026-09-21 fixes (commit 7bccbf4c: compact coverage, run detail disclosures, stop-reason copy, document titles, focus ring, retry consistency). Evidence: 92 states captured at 1440 px and 25 at 390 px against a HEAD server on a copy of the demo database, plus a code review of `ui/src`. Legacy Runs whose Workflow versions were removed from the catalog are out of scope by user decision (old data will be deleted or hidden).

| ID | Finding | Evidence | Where |
| --- | --- | --- | --- |
| E01 | Internal-model vocabulary leaks into the interface | Eyebrows and ledes read 'IMMUTABLE TYPED INFRASTRUCTURE PATCH', 'AUTHORITATIVE PROCESS SNAPSHOT', 'ALLOCATION-ONLY HTTP CONFIGURATION', 'REUSABLE PROJECTSCOPE', 'FROZEN WORKFLOW OUTPUTS', 'Exact Audit profile'; explanatory paragraphs such as 'Idle slots do not establish compatible capacity…' appear on most pages. | Runs → Configuration detail, Operations Overview, Project Settings, Eval workspace, Run detail |
| E02 | Manual Refresh is the most prominent control on nearly every page | 'Refresh snapshot', 'Refresh configuration', 'Refresh results', 'Refresh context', 'Refresh overview', 'Refresh audits' are rendered as large primary or secondary buttons although live events and query refetch already update the views. | Operations, Runs, Audit tabs, Project overview, Artifacts |
| E03 | Headers consume the first screen | Project pages spend ~300 px on title, description, tabs and a repeated section heading; Audit pages spend ~350 px including a lone delete icon row; on 390 px the first content starts below the second viewport. | Project workspace tabs, Audit detail tabs |
| E04 | Coverage and Checks show the same 23 items twice | Coverage lists checks with outcome badges; Checks lists the same operations as 'SETTLED · trace · accepted-result · 1 attempts' cards with attempts inside a disclosure. | Audit → Coverage, Audit → Checks |
| E05 | Execution configuration is spread over three sections | RuntimeConfig versions live under Runs → Configuration; LLM configurations, Credentials and Settings under Operations; the application target under Project Settings; links between them are ad hoc (D21 carry-over). | Runs → Configuration, Operations, Project → Settings |
| E06 | Runtime Agents are identified by hashes and offline identities dominate | Cards read 'Agent · 499558…df01' with 'No process / Not observed / Not observed'; four offline identities have the same weight as live agents (D31 carry-over). | Operations → Runtime Agents |
| E07 | Legacy eval workspace duplicates the project workspace | The legacy eval page repeats artifact shortcuts, artifact library and workflow launch blocks that exist on project pages; Experiments already replace the eval model. | Evals → legacy workspace |
| E08 | Audit collections load every page and poll finished audits | collectAuditPages drains all pages; Findings, Coverage, Checks and Reviews poll every 5 s per audit including completed ones, so 'As of' timestamps churn without new data. | ui/src/api/audit-collections.ts, routes/projects/audits/* |
| E09 | Create flows use four different patterns | New Project and New Audit toggle inline forms; uploads sit in details accordions; Git import and publish use dialogs; Configure Run is a page (D22 carry-over). | Projects, Audits, Artifacts, Runs → Configuration |
| E10 | Polish: absolute dates, oversized document headings, main bundle size | Timestamps render as '9/8/2026, 1:49:35 AM' in lists; Markdown artifact previews render H1 larger than the page title; the main chunk is 1.2 MB with react-markdown inside. | Lists and cards, Artifact preview, build output |

Priorities: E01–E03 change copy and layout only and are taken first; E08 is a data-loading defect; E04–E07 and E09 change navigation or form structure; E10 is polish. Tasks: [plan](../plans/2026-09-22-ui-design-review-2.md).

# Реализация дизайн-аудита Contractor UI — 19 сентября 2026

Актуальный выпуск — **UI 0.3.1**, коммит `c030303ab81a80665836ccc484dae7e45e3ed504`, [стенд](http://127.0.0.1:4173). Пользовательские замечания после первого выпуска закрыты в [V58-013](../../tasks/v58-013-finding-text-and-run-actions.yml); [доказательства](../../tasks/evidence/v58-013.json), [галерея исправленных экранов](../../.local/ui-design-implementation/phase-013/index.html).

- Finding в обоих списках показывает полный безопасно отрисованный Markdown; переход к решению остаётся перед описанием и не перекрывает текст при прокрутке.
- Ссылки Sources открывают точную ревизию входного артефакта Audit и возвращают к исходному Finding. Структурированной ссылки на файл/строку в Finding нет; из текста она не выводится.
- Корзина Completed Runs помещается внутри ячейки с отступами. Раскрытые labels используют всю ширину строки, обычные ключи больше не разрываются на части.
- Раскрытые allocations занимают всю строку; метрики распределяются по колонкам в зависимости от доступной ширины. На 1920 px первая карточка изменилась с 341 × 677 до 1189 × 230 px, все шесть значений сохранены.

Для UI 0.3.1 прошли **47 целевых тестов**, lint/format, оба проекта TypeScript и production build. Проверены 7 состояний на 1440/390/320 px: 21 снимок до и 21 после обновления. Отдельные измерения корзины, labels и allocations охватывают 1920/1440/1024/768/390/320 px; проверены два перехода Finding → Sources → Finding. Нет ошибок JavaScript/API, переполнения документа и отправленных изменений. Браузер использовал подставленную сессию и реальные авторизованные REST-чтения.

При выпуске перезапущен сервис UI. Очередь осталась paused, revision 29; scheduler, 147 Runs, четыре Runtime identities, PID Server/Runtime/proxy и ссылка основного выпуска совпали до/после. Локальные изменения других задач сохранены. Изменение Server не требуется.

Проверки: **413 UI-тестов в 60 файлах**, **9 тестов сервиса UI**, ESLint/Prettier, оба проекта TypeScript, сверка сгенерированного API-контракта и production build прошли. Повторный прогон также исправил ожидание асинхронного рендера в тесте пагинации каталога.

В браузере проверены **105 состояний**, по одному снимку на 1440 и 390 px, плюс **8 критических состояний на 320 px**: всего **218 снимков первого экрана**, дополнительные полные страницы и 16878 семантических элементов в инвентаризации. После выпуска повторены **16 состояний на действующем UI**. Нет необработанных ошибок JavaScript, ошибок сценариев, горизонтального переполнения страницы или отправленных изменений. Браузер отдельно проверил восстановление чтения после 503 с сохранением фильтра, клавиатуру и возврат фокуса во вложенных диалогах, мобильную навигацию, выбор профиля и включение зависимых полей telemetry.

Для обхода подставлялась сессия, а REST-чтение выполнялось с действующим доступом; вход по паролю и авторизованный WebSocket этим обходом не проверялись. На наполненном стенде по-прежнему доступны не все состояния: отсутствие активных работ, ожидающих решений и LLM credentials проверялось как пустое состояние; формы и мутации дополнительно покрыты тестовыми данными. Ограничение просмотра большого ZIP Nextcloud сохранено: ответ 422 теперь даёт точную причину и действие Download, по одному ожидаемому ответу на каждой ширине.

Во время выпуска перезапущен только сервис UI. PID Server, двух Runtime и LAN proxy, основная release-ссылка, очередь, scheduler, список Runs и identities Runtime до/после совпали. Существующие локальные изменения задач сохранены. Новый UI включает и обновлённый сервис раздачи UI с HTML-страницей 404; отдельное обновление API Server для этих изменений не требуется.

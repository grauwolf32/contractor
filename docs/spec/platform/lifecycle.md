# Entity lifecycle

Requirement prefix: `LIFE` · [Specification index](../README.md)

## Purpose and scope

This document is the registry of entity lifecycles. Each entity whose
deletion, deletion blockers, cascade or retention the specification constrains
has one entry, which records what deletes the entity, what blocks its deletion,
what its deletion cascades to and what is retained. The entries owned by every
document are assembled into the [Registry](#registry) at the end of this
document.

This document owns:

- the lifecycle entry, its `LIFE-<area>-<n>` identifier and its fields;
- the forms in which entries state deleters, deletion blockers and retention;
- the rules that apply to every entry: single ownership, citation instead of
  restatement, and one entry per entity.

It leaves to other documents:

- each lifecycle rule itself, stated by the owning requirement that the
  registry row links to. For example, the retention and cleanup of durable
  telemetry belong to [Observability](observability.md); the deletion
  blockers of RuntimeConfig versions, label bindings and encrypted credentials
  to [Runtime configuration](../configuration/runtime-config.md); the retention
  of Skill package revisions and Run skill forks to
  [Skills](../tools/skills.md);
- the destructive lifecycle controls: terminal Run hard deletion, recoverable
  Project deletion, the controlled scope purge and reference-safe garbage
  collection: [Retention and deletion](../artifacts/retention-and-deletion.md);
- numeric bounds such as retention periods: [Limits](limits.md); error codes:
  [Errors](errors.md); outcome classes of failed calls and mutations:
  [Failure model](failure-model.md).

The place of registries in the specification is set out in the
[conventions](../conventions.md#registries).

## Concepts

Terms are defined once in the [glossary](../glossary.md); this document owns
the following ones.

- **Lifecycle entry.** The one registry row `LIFE-<area>-<n>` for an entity,
  where `<area>` is the requirement prefix of the owning document and `<n>`
  numbers the entries that document owns.
- **Deletion blocker.** A reference, a state or a prerequisite that prevents
  an entity from being deleted while it holds.
- **Cascade.** The deletion of other entities or records that the deletion of
  an entity causes.
- **Retention.** How long an entity, or a version of it, stays stored or
  readable, for example for a fixed period, without ever being purged, while
  something refers to it, or for the lifetime of another entity.

## Model

### Lifecycle entry

| Field | Content |
| --- | --- |
| ID | `LIFE-<area>-<n>` |
| Entity | The entity, or the kind of version or record of it, whose lifecycle is constrained |
| Deleted by | The actor or process that deletes the entity |
| Blocked by | Every deletion blocker |
| Cascades | What the deletion of the entity also deletes |
| Retained | What stays stored or readable, and for how long |
| Owner | A link to the owning requirement |

A field that the owning requirements leave open reads "not specified".

### Field forms

Owning requirements state lifecycles in forms such as the ones below; the list
is not exhaustive. Each example names the entity and its owner; the rule itself
is in the linked requirement.

| Field | Form | Examples |
| --- | --- | --- |
| Deleted by | Batch-bounded cleanup after a retention period, with a bounded deletion budget per table | Durable telemetry: LIFE-OBS-2 ([OBS-R43](observability.md), [OBS-R44](observability.md)) |
| Deleted by | Never: the entity may be atomically rebound but not removed | Default binding: LIFE-RCF-4 ([RCF-R126](../configuration/runtime-config.md)) |
| Blocked by | A holder that pins or references it: an active label binding, a non-terminal Run snapshot or a live allocation | Immutable RuntimeConfig version: LIFE-RCF-3; encrypted credential, LLM or runtime: LIFE-RCF-1, LIFE-RCF-5 ([RCF-R128](../configuration/runtime-config.md), [RCF-R54](../configuration/runtime-config.md)) |
| Blocked by | The state of the entity the record belongs to: cleanup may delete only records whose parent entity is terminal | Durable telemetry of a StageExecution: LIFE-OBS-2 ([OBS-R43](observability.md)) |
| Blocked by | A prerequisite removal from other entities | Label binding, whose label is carried by Runtime Agents: LIFE-RCF-4 ([RCF-R129](../configuration/runtime-config.md)) |
| Retained | A fixed period | Durable telemetry: LIFE-OBS-2, LIM-OBS-8 ([OBS-R43](observability.md)) |
| Retained | Never purged | Owner UserScope skill package revisions: LIFE-SKL-1 ([SKL-R81](../tools/skills.md)) |
| Retained | Readable while a retained Run snapshot refers to it | Exact owner source and Run fork revisions: LIFE-SKL-1, LIFE-SKL-2 ([SKL-R81](../tools/skills.md)) |
| Retained | For the lifetime of another entity | Run skill fork, which lives as long as its Run: LIFE-SKL-2 ([SKL-R81](../tools/skills.md)) |

## Requirements

**LIFE-R1.** Every entity whose deletion, deletion blockers, cascade or
retention the specification constrains has exactly one lifecycle entry
`LIFE-<area>-<n>`, where `<area>` is the requirement prefix of the document
that owns the entity's lifecycle rules.

Rationale: a lifecycle rule that several components enforce stays consistent
only when it is defined in one place.

**LIFE-R2.** The owning document states an entity's lifecycle rules as
requirements and cites the entry where it states them.

**LIFE-R3.** An entry names every deleter, deletion blocker, cascade and
retention that its owning requirements give for the entity; several holders
that constrain one entity do not get separate entries. For example, the one
entry of an immutable RuntimeConfig version (LIFE-RCF-3) names the active label
binding, the non-terminal Run snapshot and the live allocation, each of which
blocks its deletion ([RCF-R128](../configuration/runtime-config.md)).

**LIFE-R4.** A document that depends on a lifecycle rule owned elsewhere links
to the owning requirement or to the entry and does not restate the rule. For
example, the retention of durable telemetry is stated once by
[OBS-R43](observability.md) (LIFE-OBS-2), and the deletion blockers of
RuntimeConfig versions and encrypted credentials once by
[RCF-R128](../configuration/runtime-config.md) and
[RCF-R54](../configuration/runtime-config.md) (LIFE-RCF-3, LIFE-RCF-1,
LIFE-RCF-5).

## Limits, failures and errors

This document owns no bound, error code or failure outcome. Lifecycle rules
that carry a bound cite its entry in the [limits registry](limits.md), such as
the retention of durable telemetry for 30 days (LIM-OBS-8,
[OBS-R43](observability.md)); the bounded deletion budget of each telemetry
table is stated by [OBS-R44](observability.md).

## Non-goals

- Physical garbage collection of unreferenced immutable RuntimeConfig
  versions, which may be retained indefinitely, and garbage collection of
  unreferenced historical Skill packages. Both deferrals are owned by their
  documents: [Runtime configuration](../configuration/runtime-config.md#non-goals)
  and [Skills](../tools/skills.md#non-goals).

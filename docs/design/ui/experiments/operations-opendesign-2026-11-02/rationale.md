# Rationale — Operations overview v1

Hierarchy leads with the slot distribution: the Execution slots panel gets a stronger border, a taller track with a sunken backing and minimum-width segments so single-slot states stay visible, and a grid legend with mono counts, while the snapshot counts above it are compacted into an uppercase micro-label band with 1.25rem mono numerals.
Inspection is qualified, not alarmist — the Needs inspection panel only takes a warning border and heading tone when the controller reports mismatches, and each item keeps its plain-language qualification, mono process link and divider rhythm, with the draining note separated below.
Process rows and allocation rows stay related (same card, hover, and rotating disclosure chevron) but distinct: allocation rows tint their icon with the accent and show the authoritative phase as a filled chip against the observed phase as an outline chip, while process rows keep neutral icons that turn warning only on `data-warning=true` rows carrying a reconciliation reason or ID difference.
Section navigation is labelled and structural: a sticky card at ≥821px with a hover surface, a selected bar on the current item, and a divider above the Setup group, folding at ≤820px into the seed's bordered, labelled block rather than an icon rail.
Disclosures sink to `--surface-subtle` with uppercase fact labels, mono values and row dividers so exact IDs, heartbeat, lease and capabilities stay readable on demand, and empty or failed reads keep explicit dashed boxes and a danger-tinted panel instead of any fabricated health.
Mobile treatment is progressive: the header stacks at 640px, and at 480px the slot legend drops to two columns and the process summary restacks to heading / state chip / context so nothing truncates, all using only the supplied theme tokens, spacing scale and the two app font families.

## Current domain — do not invent fields

Engagement is one typed immutable Artifact revision, with schema=contractor.engagement.v1, egress={routes,exclusions}, identities and optional limits. A route has exact canonical origin, pathPrefixes, methods and addressRanges (CIDRs); exclusion rules win. A policy has exactly one anonymous identity without credentials and up to seven other identities. Other kinds are Basic/Bearer/supplied cookies, with references to existing matching credential kinds. No secret values are read or stored in policy. Role and tenant are declarations, never verified login state. No login wizard, refresh token operation, source-mode switch, audit budgets, workflow capability selectors, default quotas or global usage counters.

The five optional limits are targetRequests, requestsPerSecond, concurrentRequests, requestBodyBytes and responseBodyBytes. Each is an optional positive uint32 value; absent means not configured. These limits apply independently to each allocation, not cumulatively across an Audit. Source materials, execution budgets/deadlines and capabilities remain with the ordinary Audit/Run/Workflow editors. The existing ordinary Run can bind an engagement as a typed exact input; there is no special launcher or mandatory Audit dependency for this editor.

## Composition and states

Inside .eg-frame: .eg-rail is the existing app navigation. .eg-workspace contains .eg-page-header, local .eg-tabs links, and .eg-layout with .eg-content plus .eg-summary. .eg-section owns a heading with icon, eyebrow, title, description and actions. Route rows are .eg-route; fields are .eg-field; identity rows .eg-identity; limits .eg-limit-grid. Summary should feel like a precise non-secret policy receipt, with counts, edit status and exact revision; it must wrap below content on small widths. Use restrained accent colors for Network/Identity/Limits, especially colored small icon surfaces and selected method chips. Make add/remove actions clear. Maintain visible labels, touch targets, focus indicators, errors and field help. Limits may remain empty; don't make them look like required validation errors.

The seed offers normal, field-invalid, stale-revision, missing credential, Server rejection and readonly examples. Banners never claim validation proves reachability or successful authentication. Preserve form facts and values, every control, existing details disclosures, native keyboard navigation and [hidden]. No generated content text or hiding facts. Keep mobile header compact, all actions reachable, no fixed heights/overlays or horizontal page overflow. Desktop 1440/1100; mobile 390/320. At <=820 the rail collapses naturally and the summary goes below; at <=480 route/identity grids and toolbar actions wrap cleanly.

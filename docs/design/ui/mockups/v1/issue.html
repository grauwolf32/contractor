IDOR: Any authenticated user can read any mechanic's service report

GET /workshop/api/mechanic/mechanic_report · CWE-639 Authorization bypass through user-controlled key
Severity · not set yet

What we found

GetReportView.get (crapi/mechanic/views.py, lines 214–244) answers this endpoint and is protected only by @jwt_auth_required, which checks that the caller is signed in and nothing more. On line 235, ServiceRequest.objects.filter(id=report_id).first() loads the report by its id without tying it to the caller.

Sibling views in the same file get this right: line 269 filters by mechanic__user=user, and line 304 checks the mechanic role.

Why it matters

Any signed-in user, including a customer who registered themselves, can step through sequential report_id values and read every service report: the owner's email and phone number, the vehicle's VIN and the problem details.

Evidence

  • crapi/mechanic/views.py:235 The report lookup by id is not limited to the caller.
  • crapi/mechanic/views.py:213-214 Only the sign-in decorator; no role or ownership check.
  • crapi/mechanic/views.py:269 A sibling view that correctly limits results to the caller.
  • crapi/mechanic/serializers.py:40-72 The response includes the owner's personal data.
  • utils/jwt.py:61-65 Loads the user from the token; never checks their role.

How sure we are

Clear in the code: line 235 ignores who is asking, while the sibling views on lines 269 and 304 do not.

Not visible to us: how the external identity service issues the token a caller needs.
